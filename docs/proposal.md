## 2. 개발 배경 및 필요성

### 2.1. 기존 수학 증명 방식의 한계

전통적인 수학적 증명은 자연어와 수학 기호를 이용하여 작성되며, 증명의 타당성은 전문가의 검토에 의존한다.

그러나 현대 수학의 연구 난도가 증가하고 증명의 규모와 복잡성이 확대됨에 따라 다음과 같은 문제가 발생한다.

- 복잡한 수학적 증명의 오류 검출 한계
- 암묵적 가정과 논리적 비약의 검증 어려움
- 대규모 증명에 대한 전문가 검토 부담 증가
- 기존 수학적 지식의 체계적인 재사용 어려움
- 인공지능이 생성한 수학적 증명의 신뢰성 문제
- 수학적 지식을 기계가 처리할 수 있는 형태로 구조화하는 데 따른 어려움

이러한 문제를 해결하기 위해 Lean, Rocq(Coq), Isabelle, HOL Light 등의 형식적 정리 증명 시스템이 개발되어 왔다.

### 2.2. 기존 수학 증명 언어의 한계

기존 정리 증명 언어는 높은 수준의 수학적 엄밀성을 제공하지만, 일반적인 프로그래밍 개발자와 인공지능 연구자가 접근하기에는 진입 장벽이 존재한다.

특히 새로운 언어 문법과 타입 시스템, 증명 전술, 라이브러리 구조 등을 학습해야 하며, 기존 인공지능 및 과학 계산 환경과의 연계에도 추가적인 개발이 필요하다.

Python은 과학 계산, 인공지능, 데이터 분석, 기호 수학 및 수치해석 분야에서 널리 활용되고 있으나, 언어 자체에는 범용적인 형식적 수학 증명 기능이 포함되어 있지 않다.

따라서 Python의 접근성과 확장성을 기반으로 형식적 수학 증명 기능을 제공하는 새로운 증명 언어의 개발이 필요하다.

## 4. 핵심 개발 철학

AxiomWeave는 다음 다섯 가지 원칙을 기반으로 설계한다.

| 원칙          | 설명                                              |
| ------------- | ------------------------------------------------- |
| Accessibility | Python 개발자가 쉽게 학습하고 활용할 수 있는 문법 |
| Soundness     | 선언된 논리 체계에서 증명된 명제만 정리로 인정    |
| Extensibility | 새로운 자료형, 수학 이론, 증명 전술 추가 지원     |
| Verifiability | 모든 증명 과정에 대한 독립적 검증 및 재현         |
| AI-Native     | 인공지능 기반 증명 탐색을 고려한 내부 구조 설계   |

수학적 증명을 생성하는 시스템과 증명의 타당성을 검증하는 시스템을 명확하게 분리한다.

인공지능이나 자동 증명 엔진이 생성한 결과는 자체적으로 신뢰하지 않으며, 검증 커널을 통과한 증명만 정식 수학 정리로 등록한다.

## 5. 언어 설계

### 5.1. 기본 설계 방향

AxiomWeave는 Python 인터프리터 자체를 수정하지 않고, Python의 다음 기능을 활용하는 임베디드 도메인 특화 언어(Embedded DSL) 방식으로 개발한다.

- 클래스 및 객체지향 프로그래밍
- 연산자 오버로딩
- 데코레이터
- 타입 어노테이션
- 추상 구문 트리(AST)
- 함수형 프로그래밍
- 메타프로그래밍

초기에는 표준 Python 파일에서 사용할 수 있는 라이브러리로 구현하며, 이후 수학적 표현에 특화된 `.axw` 전용 문법과 파서를 추가한다.

정의, 정리 및 증명은 명시적인 `Theory` 객체(`thy = Theory("...")`)에 등록하며, 커널 검증은 `thy.check()`를 호출할 때 선언 순서대로 수행한다. 이 절의 예제는 설계 방향을 보여주는 예시이며, v0.1 API의 규범적 정의는 [language-spec.md](language-spec.md)를 따른다.

### 5.2. 수학적 자료형

| 자료형           | 의미        |
| ---------------- | ----------- |
| Prop             | 수학적 명제 |
| Type             | 수학적 타입 |
| Nat              | 자연수      |
| Int              | 정수        |
| Rational         | 유리수      |
| Real             | 실수        |
| Complex          | 복소수      |
| Set              | 집합        |
| Function         | 수학적 함수 |
| Sequence         | 수열        |
| Vector           | 벡터        |
| Matrix           | 행렬        |
| Group            | 군          |
| Ring             | 환          |
| Field            | 체          |
| MetricSpace      | 거리 공간   |
| TopologicalSpace | 위상 공간   |

모든 자료형은 형식적인 수학적 의미를 가지며, 일반적인 Python의 수치 계산 객체와 구분한다.

예를 들어 Real은 부동소수점 자료형이 아니라 수학적 실수를 나타내는 추상적 타입으로 정의한다.

### 5.3. 논리 연산자

| 수학적 표현          | AxiomWeave 문법                   |
| -------------------- | --------------------------------- |
| $\forall x,\ P(x)$   | `ForAll(x, P(x))`                 |
| $\exists x,\ P(x)$   | `Exists(x, P(x))`                 |
| $P \land Q$          | `And(P, Q)` 또는 `P & Q`          |
| $P \lor Q$           | `Or(P, Q)` 또는 `P \| Q`          |
| $\lnot P$            | `Not(P)` 또는 `~P`                |
| $P \to Q$            | `Implies(P, Q)` 또는 `P >> Q`     |
| $P \leftrightarrow Q$ | `Iff(P, Q)`                      |
| $x = y$              | `Eq(x, y)`                        |
| $x \neq y$           | `Ne(x, y)`                        |
| $x \in A$            | `Contains(A, x)`                  |
| $A \subseteq B$      | `Subset(A, B)`                    |

Python의 일반 Boolean 값과 수학적 명제는 엄격하게 구분한다.

기호 명제의 암묵적인 Boolean 변환과 Python의 연쇄 비교는 금지하여, 수학적 표현이 일반 Python 연산으로 잘못 평가되는 것을 방지한다.

Python의 `>>`는 좌결합이고 우선순위가 `&`, `|`보다 높아 논리 관례와 다르므로, `>>`를 연쇄하지 않고 연쇄 함의는 `Implies(A, B, C)`로 작성하며, 서로 다른 연산자를 섞을 때는 괄호를 사용한다.

### 5.4. 수학적 명제 표현

모든 실수의 제곱이 음수가 아니라는 명제를 다음과 같이 표현할 수 있도록 설계한다.

```python
from axiomweave import *

thy = Theory("demo.real")
x = Symbol("x", Real)

P = ForAll(x, x**2 >= 0)
```

이때 P는 참 또는 거짓의 단순한 Boolean 값이 아니라, 증명할 수 있는 수학적 명제 객체이다.

### 5.5. 수학적 함수 정의

```python
@thy.definition
def square(x: Real) -> Real:
    return x * x
```

수학적 정의에 해당하는 Python 함수는 임의의 실행 코드가 아니라 제한된 문법을 통해 형식적인 수학 표현으로 변환한다.

### 5.6. 정리 선언

```python
@thy.theorem
def square_nonnegative(x: Real) -> Prop:
    return square(x) >= 0
```

`@thy.theorem`은 증명할 명제를 등록하는 역할을 수행한다.

해당 명제가 커널에서 검증(`VERIFIED`)되기 전까지는 다른 정리의 증명에 사용할 수 없다.

### 5.7. 증명 작성

```python
@thy.proof(square_nonnegative)
def square_nonnegative_proof(ctx):
    x = ctx.intro()

    ctx.unfold(square)
    ctx.exact(mul_self_nonnegative(x))
```

증명 함수는 등록만 되며, `thy.check()` 호출 시 각 단계가 내부 증명 객체로 변환되고 검증 커널이 논리적인 타당성을 검사한다.

### 5.8. 가정과 중간 정리를 이용한 증명

```python
@thy.theorem
def positive_square(x: Real) -> Prop:
    return Implies(x > 2, x**2 > 4)


@thy.proof(positive_square)
def prove_positive_square(ctx):
    x = ctx.intro()
    h = ctx.intro()

    h1 = ctx.have(x - 2 > 0, by=linarith(h))
    h2 = ctx.have(x + 2 > 0, by=linarith(h))

    h3 = ctx.have((x - 2) * (x + 2) > 0, by=mul_pos(h1, h2))

    ctx.exact(nlinarith(h3))
```

이와 같은 문법을 통해 수학자가 일반적으로 작성하는 단계별 증명 과정을 Python으로 표현할 수 있도록 한다.

### 5.9. 수학적 귀납법

```python
@thy.theorem
def zero_add(n: Nat) -> Prop:
    return Eq(0 + n, n)


@thy.proof(zero_add)
def prove_zero_add(ctx):
    n = ctx.intro()

    with ctx.induction(n) as ind:
        with ind.base():
            ctx.rfl()

        with ind.step() as (k, ih):
            ctx.rewrite(ih)
            ctx.rfl()
```

자연수에 대한 귀납법뿐만 아니라 재귀적으로 정의된 수학적 자료형에 대한 구조적 귀납법도 지원하도록 확장한다.

## 7. 핵심 기술 개발 내용

### 7.1. 수학적 중간 표현 시스템

수학적 표현을 프로그래밍 언어의 실행 결과와 분리하여 구조화된 트리로 표현한다.

예를 들어 $x^2 + 2x + 1$은 다음과 같은 내부 구조로 변환한다.

```text
Add
├── Add
│   ├── Power
│   │   ├── Variable(x)
│   │   └── Constant(2)
│   └── Multiply
│       ├── Constant(2)
│       └── Variable(x)
└── Constant(1)
```

주요 내부 표현 객체는 다음과 같다.

- Constant
- Variable
- BoundVariable
- FunctionApplication
- Lambda
- Equality
- Proposition
- Quantifier
- Implication
- TypeExpression
- InductiveType
- ProofTerm

변수의 유효 범위 관리, 변수 포획 방지, 타입 일치 검사, 수학적 정의의 전개 및 치환 등을 지원한다.

### 7.2. 형식 논리 및 타입 시스템

논리 체계는 단순 타입 이론(Simple Type Theory)을 기반으로 설계하며, 최초 구현 및 검증 대상은 그 안의 직관주의 명제 논리 단편(L0)이다. 고전 논리 원리(배중률 등)는 기본 규칙에 포함하지 않고 이름 있는 공리로 등록하여 의존성을 추적한다.

이후 다음 단편을 단계적으로 확장한다. 단편 구분은 [specification.md](specification.md) §4.4를 따른다.

| 단편 | 내용                                         |
| ---- | -------------------------------------------- |
| L0   | 직관주의 명제 논리 (자연 연역)               |
| L1   | 람다 추상, 기본 타입, 전칭·존재 양화사       |
| L2   | 등식과 등식 추론                             |
| L3   | 자연수와 귀납 원리                           |
| L4   | 고차 논리                                    |
| L5   | 다형성, 귀납적 자료형, 의존 타입 (장기 연구) |

타입 유니버스와 재귀적 타입은 L5 이후의 연구 과제로 둔다. 초기 논리 체계와 장기적인 의존 타입 체계 사이에는 형식적 변환 규칙을 정의한다.

의존 타입 체계는 별도의 후속 연구 목표로 설정하며, 초기 커널에 검증되지 않은 논리 규칙을 추가하지 않는다.

### 7.3. 독립적인 증명 검증 커널

검증 커널은 AxiomWeave의 가장 중요한 구성 요소이다.

주요 기능은 다음과 같다.

- 명제 및 증명 객체의 타입 검사
- 논리적 추론 규칙 검증
- 자유 변수 및 바인딩된 변수 검사
- 정의의 전개와 치환 검증
- 귀납법 및 재귀 정의의 정당성 검사
- 공리 의존성 추적
- 순환적 증명 참조 검출
- 미완성 증명 검출
- 증명 객체의 독립적인 재검증

핵심 검증 커널은 가능한 한 작고 단순하게 구현하여 검증 대상 코드의 규모를 최소화한다.

증명 전술, 사용자 플러그인 및 인공지능은 커널의 내부 상태나 신뢰된 정리 저장소를 직접 변경할 수 없도록 설계한다.

외부 코드를 실행하는 환경과 검증 환경을 별도 프로세스로 분리하고, 검증 커널은 구조화된 데이터 형태의 증명 객체만 입력받도록 한다.

### 7.4. 증명 전술 엔진

증명 전술은 현재의 수학적 목표를 해결하거나 더 작은 하위 목표로 분리하는 기능이다.

| 전술          | 기능                      |
| ------------- | ------------------------- |
| intro         | 변수 및 가정 도입         |
| exact         | 목표에 해당하는 증명 제시 |
| apply         | 기존 정리 적용            |
| rewrite       | 등식을 이용한 치환        |
| simplify      | 수학적 표현 단순화        |
| unfold        | 정의 전개                 |
| rfl           | 정의적 동일성 증명        |
| induction     | 수학적 귀납법             |
| cases         | 경우 분리                 |
| contradiction | 모순을 이용한 증명        |
| have          | 중간 명제 도입            |
| exists        | 존재 명제의 증명          |
| ring          | 다항식 등식 증명          |
| linarith      | 선형 산술 추론            |
| nlinarith     | 비선형 산술 추론          |
| auto          | 자동 증명 탐색            |
| ai_prove      | 인공지능 기반 증명 탐색   |

위 표는 1차년도 전체의 목표 전술이며, v0.1(L0)에서 제공하는 전술은 [language-spec.md](language-spec.md) §6에서 정의한다. 모든 전술은 커널이 검증하는 추론 규칙 적용만 생성해야 한다.

새로운 증명 전술을 Python 함수 또는 클래스로 추가할 수 있는 플러그인 구조를 개발한다.

### 7.5. 외부 수학 시스템 연계

| 시스템   | 활용 목적                              |
| -------- | -------------------------------------- |
| SymPy    | 기호 연산, 수식 변환, 대수적 단순화    |
| SageMath | 고급 정수론 및 대수학 계산             |
| Z3       | 논리 및 제약 조건 기반 자동 추론       |
| cvc5     | SMT 기반 자동 추론 및 증명 인증서 활용 |
| Lean     | 형식적 증명 검증 및 Mathlib 연계       |
| NumPy    | 수치 실험 및 수학적 패턴 탐색          |

외부 시스템의 계산 또는 추론 결과를 그 자체로 증명으로 인정하지 않는다.

가능한 경우 외부 시스템의 증명 인증서를 AxiomWeave의 증명 객체로 변환하거나, 내부 증명 전술을 통해 동일한 결과를 재구성하여 검증한다.

### 7.6. Lean 호환 및 교차 검증 시스템

AxiomWeave는 독립적인 수학 증명 시스템을 지향하되, 초기 개발의 효율성과 검증 신뢰도를 높이기 위해 Lean과의 연계 기능을 제공한다.

- AxiomWeave 수학 표현의 Lean 코드 변환
- Lean 정리 및 정의 검색
- Mathlib 정리와 AxiomWeave 정리의 의미적 대응
- 지원되는 논리 범위에서 양방향 증명 변환
- Lean 커널과 자체 커널을 이용한 교차 검증

다만 Lean에서 검증된 정리가 자동으로 AxiomWeave의 자체 커널에서 검증된 것으로 처리되지 않도록 검증 등급을 구분한다.

## 10. 응용 사례

### 10.1. 수학적 난제의 형식적 표현

리만 가설을 AxiomWeave로 표현하면 다음과 같은 형태가 된다.

```python
from axiomweave import *
from axiomweave.lib.number_theory import number_theory, zeta

thy = Theory("demo.riemann", imports=[number_theory])


@thy.theorem
def riemann_hypothesis(s: Complex) -> Prop:

    n = Symbol("n", Nat)

    trivial_zero = Exists(
        n,
        Eq(s, -2 * (n + 1))
    )

    return Implies(
        And(
            Eq(zeta(s), 0),
            Not(trivial_zero),
            Ne(s, 1)
        ),
        Eq(s.real, Rational(1, 2))
    )
```

이러한 방식으로 현대 수학의 복잡한 명제를 기계가 처리할 수 있는 형태로 표현한다.

단, 실제 형식화를 위해서는 리만 제타 함수와 복소해석학의 관련 정의를 엄밀하게 구축해야 한다.

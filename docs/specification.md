# AxiomWeave 명세 개요 (Specification Overview)

> **문서 상태:** 초안(Draft) · 대상 버전 v0.1 · 로드맵 M0 산출물  
> 이 문서는 AxiomWeave 명세 체계의 최상위 문서이다. 논리 체계, 언어, 커널의 세부 규칙은 하위 명세 문서에서 정의하며, 이 문서는 공통 용어, 핵심 설계 결정, 문서 간 관계 및 v0.1 적합성 기준을 정리한다.

## 1. 목적과 범위

이 문서는 다음을 정의한다.

- AxiomWeave 명세 문서의 구성과 우선순위
- 모든 하위 명세가 공유하는 용어
- 논리 기반(Simple Type Theory)과 최초 구현 대상(직관주의 명제 논리)에 관한 결정
- 표현식, 증명 객체, 커널, 언어 계층의 역할과 경계
- v0.1 릴리스의 적합성(Conformance) 기준
- 하위 명세에서 확정해야 할 미결 사항

이 문서는 세부 추론 규칙의 형식적 정의, 직렬화 형식, Python API 시그니처를 확정하지 않는다. 해당 내용은 [2. 문서 체계](#2-문서-체계)에 나열한 하위 명세에서 정의한다.

### 1.1. 규범적 표현

| --------------- | ------------------------------------ |
| ~해야 한다      | 필수 요구사항 (MUST)                 |

## 3. 용어

| 용어                     | 정의                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 타입 (Type)              | 항을 분류하는 단순 타입. 기본 타입과 함수 타입 $\sigma \to \tau$로 구성된다.                     |
| 항 (Term)                | 변수, 상수, 적용, 람다 추상으로 구성되는 단순 타입 람다 계산의 식                      |
| 명제 (Proposition)       | 타입 $\mathsf{Prop}$을 갖는 항                                                                  |
| 문맥 (Context)           | 증명 중 사용 가능한 이름 붙은 가정들의 유한한 모임 $\Gamma$                                 |
| 판단 (Judgment)          | 커널이 검사하는 주장. v0.1의 핵심 판단은 $\Gamma \vdash P$ (문맥 $\Gamma$에서 명제 $P$가 도출됨)이다. |
| 추론 규칙 (Rule)         | 전제 판단들로부터 결론 판단을 도출하는 규칙                                            |
| 증명 객체 (Proof Object) | 추론 규칙의 적용을 기록한 데이터 구조. Python 코드를 포함하지 않는다.                  |
| 인증서 (Certificate)     | 증명 객체에 명제, 의존성, 버전 정보를 결합한 직렬화 단위 (`.axwp`)                     |
| 환경 (Environment)       | 순서가 있는 선언(공리, 정의, 정리)의 목록                                              |
| 공리 (Axiom)             | 증명 없이 환경에 등록된 명제. 모든 사용이 추적된다.                                    |
| 정리 (Theorem)           | 커널이 증명 객체를 검증하여 환경에 등록한 명제                                         |
| 전술 (Tactic)            | 증명 객체 생성을 돕는 비신뢰 절차. 결과는 반드시 커널이 검증한다.                      |
| 커널 (Kernel, AxiomCore) | 증명 객체를 검증하는 최소 신뢰 구성 요소                                               |
| 신뢰 기반 (TCB)          | 그 정확성을 가정해야 검증 결과를 믿을 수 있는 코드와 명세의 집합                       |
| 단편 (Fragment)          | 전체 논리 체계 중 특정 버전의 커널이 수용하는 부분 집합                                |

## 4. 논리 기반

### 4.1. 기반 이론: 단순 타입 이론

AxiomWeave의 항과 타입 언어는 Church 방식의 단순 타입 이론(Simple Type Theory)을 기반으로 설계한다.

$$
\begin{array}{lrcll}
\text{타입} & \sigma, \tau & ::= & \mathsf{Prop} \mid B \mid \sigma \to \tau & (B\text{: 향후 추가되는 기본 타입, 예: Nat}) \\
\text{항} & s, t & ::= & x \mid c \mid s\ t \mid \lambda x{:}\sigma.\, t &
\end{array}
$$

- 모든 항은 유일한 타입을 가져야 한다.
- 항의 동등성은 최소한 α-동치(α-equivalence)를 포함해야 한다. L0에는 바인더가 없으므로 동등성은 구문적 동일성이며, β·η 변환과 정의 전개(δ)는 포함하지 않는다 ([logic-spec.md §3.6](logic-spec.md#36-항의-동등성)).
- 논리 연산자는 타입이 지정된 상수로 표현한다. 이 설계는 이후 양화사($\forall_\sigma : (\sigma \to \mathsf{Prop}) \to \mathsf{Prop}$)와 고차 논리로 확장할 때 항 언어를 바꾸지 않기 위한 것이다.

### 4.2. v0.1 구현 대상: 직관주의 명제 논리

v0.1 커널은 단순 타입 이론 중 다음 단편만 수용해야 한다.

**원시 상수**

| 상수      | 타입                                                    | DSL 표기    |
| --------- | ------------------------------------------------------- | ----------- |
| $\bot$    | $\mathsf{Prop}$                                         | `Falsehood` |
| $\land$   | $\mathsf{Prop} \to \mathsf{Prop} \to \mathsf{Prop}$     | `And`       |
| $\lor$    | $\mathsf{Prop} \to \mathsf{Prop} \to \mathsf{Prop}$     | `Or`        |
| $\to$     | $\mathsf{Prop} \to \mathsf{Prop} \to \mathsf{Prop}$     | `Implies`   |

**명제 원자 (명제 변수):** 타입 $\mathsf{Prop}$을 갖는 이름(예: $P$, $Q$, $R$). 정리와 공리에서는 스키마 변수로 해석한다 ([logic-spec.md §3.3](logic-spec.md#33-명제-원자)).

**파생 연산자 (정의이며 원시 상수가 아님)**

| 연산자                | 정의                                    |
| --------------------- | --------------------------------------- |
| $\lnot P$             | $P \to \bot$                            |
| $\top$                | $\bot \to \bot$                         |
| $P \leftrightarrow Q$ | $(P \to Q) \land (Q \to P)$             |

**추론 규칙 (자연 연역, 판단 $\Gamma \vdash P$)**

| 규칙                 | 형태                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| $\mathrm{Hyp}$       | $h : P \in \Gamma$ 이면 $\Gamma \vdash P$                                                                    |
| $\land\mathrm{I}$    | $\Gamma \vdash P$, $\Gamma \vdash Q$ $\Rightarrow$ $\Gamma \vdash P \land Q$                                 |
| $\land\mathrm{E}_1$  | $\Gamma \vdash P \land Q$ $\Rightarrow$ $\Gamma \vdash P$                                                    |
| $\land\mathrm{E}_2$  | $\Gamma \vdash P \land Q$ $\Rightarrow$ $\Gamma \vdash Q$                                                    |
| $\lor\mathrm{I}_1$   | $\Gamma \vdash P$ $\Rightarrow$ $\Gamma \vdash P \lor Q$                                                     |
| $\lor\mathrm{I}_2$   | $\Gamma \vdash Q$ $\Rightarrow$ $\Gamma \vdash P \lor Q$                                                     |
| $\lor\mathrm{E}$     | $\Gamma \vdash P \lor Q$, $\Gamma, h_1 : P \vdash R$, $\Gamma, h_2 : Q \vdash R$ $\Rightarrow$ $\Gamma \vdash R$ |
| $\to\mathrm{I}$      | $\Gamma, h : P \vdash Q$ $\Rightarrow$ $\Gamma \vdash P \to Q$                                               |
| $\to\mathrm{E}$      | $\Gamma \vdash P \to Q$, $\Gamma \vdash P$ $\Rightarrow$ $\Gamma \vdash Q$                                   |
| $\bot\mathrm{E}$     | $\Gamma \vdash \bot$ $\Rightarrow$ $\Gamma \vdash P$                                                         |
| $\mathrm{Thm}$       | 환경의 정리 $n : A$와 치환 $\sigma$ $\Rightarrow$ $\Gamma \vdash A[\sigma]$                                  |
| $\mathrm{Ax}$        | 환경의 공리 스키마 $n : A$와 치환 $\sigma$ $\Rightarrow$ $\Gamma \vdash A[\sigma]$                           |

- 위 규칙 외의 추론은 커널에서 허용해서는 안 된다.
- $\mathrm{Thm}$과 $\mathrm{Ax}$는 명제 양화가 없는 L0에서 정리와 공리를 명제 원자에 대한 균일 치환으로 재사용하기 위한 인스턴스화 규칙이다.
- 람다 추상, 양화사, 등식, $\mathsf{Prop}$ 이외의 기본 타입을 포함한 항은 v0.1 커널이 명시적 오류로 거부해야 한다. 무시하거나 부분적으로 처리해서는 안 된다.
- 규칙의 정확한 형식(가정 이름의 해제 방식, 약화(Weakening) 처리 등)은 [logic-spec.md §8](logic-spec.md#8-추론-규칙)을 따른다.

### 4.3. 고전 논리 원리

- 배중률($P \lor \lnot P$), 이중 부정 제거($\lnot\lnot P \to P$) 등 고전 원리는 기본 규칙에 포함해서는 안 된다.
- 고전 원리는 이름 있는 공리 스키마로만 등록할 수 있으며, 이를 사용한 정리는 의존 공리 목록에 해당 공리를 기록해야 한다.
- 정리 조회 시 고전 원리 의존 여부를 확인할 수 있어야 한다.

### 4.4. 확장 경로

다음 순서로 단편을 확장한다. 각 단계는 `logic-spec.md` 개정, 실패 사례 테스트 추가, 커널 검토를 거친 뒤에만 커널에 반영해야 한다.

| 단계 | 추가 내용                                          | 로드맵    |
| ---- | -------------------------------------------------- | --------- |
| L0   | 직관주의 명제 논리 (이 문서의 v0.1 단편)           | M1–M2     |
| L1   | 람다 추상, 기본 타입, 전칭·존재 양화사 (일차 단편) | M3        |
| L2   | 등식과 등식 추론                                   | M3        |
| L3   | 자연수와 귀납 원리                                 | M3        |
| L4   | 고차 논리 (양화 대상을 함수·명제 타입으로 확장)    | 이후      |
| L5   | 다형성, 귀납적 자료형, 의존 타입                   | 장기 연구 |

의존 타입 체계는 별도 논리 명세와 검증을 거쳐 도입하며, 검증되지 않은 규칙을 기존 커널에 추가해서는 안 된다.

## 5. 구성 계층과 경계

```text
 Python DSL (language-spec)          비신뢰
        │  elaboration
        ▼
 표현식 IR / 증명 상태                비신뢰 (생성)
        │  전술·외부 도구·AI가 증명 객체 생성
        ▼
 증명 객체 / 인증서 (kernel-spec)     데이터
        │  역직렬화 · 검증
        ▼
 AxiomCore 커널 (logic-spec + kernel-spec)   신뢰 기반
        │
        ▼
 환경 (검증된 정리)
```

### 5.1. 표현식

- 표현식은 불변(Immutable) 객체여야 한다.
- 표현식은 계산 결과가 아닌 구조이며, Python `bool`로 암묵 변환되어서는 안 된다.
- L0는 바인더가 없으므로 원자와 가정을 이름으로 직접 표현한다. 바인더가 생기는 L1의 이름 표현 방식(이름 기반, de Bruijn 인덱스 또는 지역 이름 없는 표현)은 그때 [kernel-spec.md](kernel-spec.md)에서 확정한다.

### 5.2. 증명 객체

- 증명 객체는 [4.2](#42-v01-구현-대상-직관주의-명제-논리)의 규칙 적용만으로 구성된 순수 데이터여야 한다.
- 증명 객체는 Python 코드, 호출 가능 객체, 외부 프로세스 참조를 포함해서는 안 된다.
- 커널은 증명 객체로부터 결론을 직접 재계산해야 하며, 증명 객체에 기록된 결론을 신뢰해서는 안 된다.
- 다른 정리의 참조는 이름과 내용 해시로 식별해야 한다.
- 증명 객체는 규칙 태그가 붙은 자연 연역 도출 트리로 인코딩한다 ([kernel-spec.md §5](kernel-spec.md#5-도출-트리-인코딩)).

### 5.3. 커널

커널은 다음을 검사해야 한다.

- 모든 항의 타입 적합성과 v0.1 단편 소속 여부
- 각 추론 단계의 규칙 적용 조건
- 가정의 도입·해제 범위와 해제되지 않은 가정의 부재
- 재계산한 결론과 선언된 명제의 일치 ([logic-spec.md §3.6](logic-spec.md#36-항의-동등성)의 동등성 기준)
- 참조한 정리가 환경에 이미 검증되어 존재하는지 여부
- 순환 참조의 부재 (환경의 선언 순서로 보장)
- 사용된 공리가 허용 목록에 있는지 여부

커널은 임의 Python 코드, 플러그인, 외부 솔버, 네트워크를 호출해서는 안 된다. 커널은 가능한 한 Python 표준 라이브러리만 사용하는 것을 권장한다.

### 5.4. 신뢰 기반

| 포함 (TCB)                         | 제외 (비신뢰)                      |
| ---------------------------------- | ---------------------------------- |
| `logic-spec.md`의 규칙 정의        | Python DSL 및 Elaborator           |
| 커널 검사기와 커널 내부 표현식 자료구조 | 전술 엔진                     |
| 인증서 역직렬화기                  | SymPy, Z3, cvc5, Lean 등 외부 도구 |
| Python 런타임                      | AxiomAI 및 탐색 알고리즘           |

비신뢰 구성 요소는 커널의 내부 상태나 환경을 직접 변경해서는 안 된다.

### 5.5. 언어

- v0.1 언어는 Python 인터프리터를 수정하지 않는 임베디드 DSL이다.
- 정리로 선언된 명제(`@thy.theorem`)는 `VERIFIED` 상태가 되기 전까지 다른 증명에서 참조할 수 없어야 한다.
- 전술은 증명 객체를 생성하는 수단일 뿐이며, 전술의 성공이 검증을 의미해서는 안 된다.
- 표면 문법, 연산자 대응, 전술 목록은 `language-spec.md`에서 정의한다. README §4의 예제는 설계 의도를 보여주는 비규범적 예시이다.

| 상태                | 의미                                                 | v0.1 |
| ------------------- | ---------------------------------------------------- | ---- |
| `UNPROVEN`          | 명제가 선언되었으나 검증된 증명이 없음               | 필수 |
| `VERIFIED`          | 자체 커널이 허용된 공리와 규칙 아래 검증함           | 필수 |
| `REJECTED`          | 증명 객체 또는 추론 단계 검증 실패                   | 필수 |
| `EXTERNAL_VERIFIED` | 명시된 외부 환경에서 검증되었으나 자체 검증은 미완료 | 예약 |

- `VERIFIED`는 사용된 논리 단편, 공리, 커널 구현의 정확성에 상대적인 결과이다.
- `EXTERNAL_VERIFIED` 정리는 `VERIFIED` 정리의 증명에 사용해서는 안 된다.
- 검증 실패나 탐색 시간 초과는 명제가 거짓임을 의미하지 않는다.

## 7. 인증서와 재현성

인증서(`.axwp`)는 최소한 다음 정보를 포함해야 한다.

- 명세 버전과 커널 버전
- 논리 단편 식별자 (v0.1은 L0)
- 명제와 증명 객체
- 참조한 정리의 이름과 내용 해시
- 의존 공리 목록
- 명제와 증명 객체의 내용 해시

동일한 인증서는 같은 버전의 커널에서 항상 같은 검증 결과를 내야 한다. 인증서는 Theory 하나의 검증에 필요한 모든 선언을 담은 자기완결 번들이며, 정규 JSON과 SHA-256 해시를 사용한다 ([kernel-spec.md §6–7](kernel-spec.md#6-인증서-번들)).

## 8. v0.1 적합성 기준

v0.1 구현은 다음을 모두 만족해야 한다.

1. [4.2](#42-v01-구현-대상-직관주의-명제-논리)의 모든 추론 규칙을 지원한다.
2. 명제 논리 증명 객체를 생성하고, 인증서로 저장한 뒤 별도 프로세스에서 독립적으로 재검증할 수 있다.
3. 다음 유형을 포함하여 사전에 정의한 잘못된 증명 테스트를 모두 거부한다.

| 실패 유형          | 예                                                  |
| ------------------ | --------------------------------------------------- |
| 규칙 전제 불일치   | $\to\mathrm{E}$에 전건이 다른 명제를 적용           |
| 해제되지 않은 가정 | $\to\mathrm{I}$ 없이 가정만으로 함의 결론을 주장    |
| 잘못된 가정 참조   | 범위를 벗어났거나 존재하지 않는 가정 이름 사용      |
| 결론 불일치        | 도출된 명제와 선언된 명제가 다름                    |
| 타입 오류          | $\mathsf{Prop}$이 아닌 항을 논리 연산자의 인자로 사용        |
| 단편 위반          | v0.1에서 양화사나 람다 항 사용                      |
| 미검증 정리 참조   | `UNPROVEN` 또는 `REJECTED` 정리를 증명에 사용       |
| 순환 참조          | 정리가 직·간접적으로 자기 자신을 참조               |
| 미등록 공리        | 허용 목록에 없는 공리 또는 선언 없는 고전 원리 사용 |
| 인증서 변조        | 명제, 증명 또는 해시를 변경한 인증서                |

4. 커널 테스트는 정상 증명보다 거부 사례를 우선하여 작성하는 것을 권장한다.

테스트 통과와 코드 커버리지는 커널의 논리적 건전성을 증명하지 않는다.

## 10. 변경 관리

- 이 문서와 하위 명세는 각각 버전을 가지며, 인증서에 기록된 명세 버전으로 검증 조건을 재현할 수 있어야 한다.
- 커널 추론 규칙, 공리, 인증서 검증의 변경은 명세 개정을 구현보다 먼저 해야 한다.
- 명세 개정에는 변경 이유, 신뢰 기반에 미치는 영향, 추가된 실패 사례 테스트를 함께 기록해야 한다.

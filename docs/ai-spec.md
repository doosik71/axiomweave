# AxiomWeave 자동화 명세 (AxiomAI Specification)

> **문서 상태:** 초안(Draft) · §3 확정 · 구현됨 (`axiomweave.ai.propositional`, `ctx.auto`) · §4 확정 · 구현됨 (`axiomweave.ai.search`, `ctx.search`, `axw search`) · §5 확정 · 구현됨 (`axiomweave.bench`, `axw bench`)  
> 상위 문서: [specification.md](specification.md). 이 문서는 증명을 자동으로 찾는 계층(AxiomAI)을 정의한다. 첫 대상은 명제 논리 결정 절차 `ctx.auto()`(§3)이고, 다음은 정리 검색 `ctx.search()`(§4)와 벤치마크 `axw bench`(§5)이다. 규범적 표현은 [specification.md §1.1](specification.md#11-규범적-표현)을 따른다.

## 1. 범위와 원칙

| 포함                                                   | 제외 (이후 개정)                                            |
| ------------------------------------------------------ | ----------------------------------------------------------- |
| 직관주의 명제 논리의 완전한 결정 절차 (§3)             | 전술 탐색 루프, 기계 학습 정책 (§6)                         |
| 목표에 맞는 정리 검색과 이름 검색 (§4)                  |                                                             |
| 문제 집합과 측정 도구 (§5)                              |                                                             |
| 찾은 증명을 기존 전술로 재생하여 도출을 만드는 방법    | 양화사·등식 추론의 자동화                                   |

다음 원칙은 이 문서의 모든 자동화에 적용한다.

1. **자동화는 비신뢰 계층이다.** 탐색기는 증명을 직접 승인하지 않는다. 찾은 증명은 기존 전술로 재생되어 일반 도출이 되고, 커널이 검사한다. 새 커널 규칙이나 공리를 추가하지 않는다.
2. **실패는 거짓이 아니다.** 탐색 실패나 한도 초과는 명제가 거짓임을 뜻하지 않는다 ([specification.md §6](specification.md#6-검증-상태)). 완전한 결정 절차가 탐색을 끝까지 마친 경우에만, 그 절차가 다루는 규칙의 범위 안에서 "도출되지 않는다"고 보고할 수 있다.
3. **결정성.** 같은 증명 상태와 같은 한도에 대해 같은 결과와 같은 도출을 만들어야 한다.
4. **한도.** 모든 탐색은 단계 수 한도를 가져야 하며, 한도 초과는 실패와 구별하여 보고한다.

## 2. 설계 결정 요약

| 항목            | 결정                                                                                         | 근거                                                    |
| --------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 첫 절차         | Dyckhoff의 G4ip(LJT) 시퀀트 계산                                                             | 축약(contraction) 없이 종료하며 직관주의 명제 논리에 완전하다. |
| 대상 논리       | 목표의 명제 골격. 양화사, 등식, 술어 적용은 불투명한 원자로 본다                              | L1·L2 목표의 명제적 부분도 다룰 수 있다.                 |
| 증명 생성       | 탐색은 순수 시퀀트 위에서 하고, 찾은 증명 트리를 기존 전술로 재생한다                          | 되돌리기(backtracking)가 증명 상태를 건드리지 않는다.    |
| 외부 의존성     | 없음                                                                                         | 표준 기능으로 항상 쓸 수 있어야 한다.                   |

## 3. 명제 논리 결정 절차

> **상태:** 확정 · 구현됨.

### 3.1. 대상

목표와 전제를 명제 골격으로 읽는다.

| 명제                                                         | 골격                                           |
| ------------------------------------------------------------ | ---------------------------------------------- |
| $\bot$, $A \land B$, $A \lor B$, $A \to B$                   | 그대로 ($\lnot A$는 $A \to \bot$, $A \leftrightarrow B$는 두 함의의 논리곱) |
| 원자 $P$, 스키마 술어, 술어 적용, 등식, $\forall$, $\exists$ | 불투명한 원자. 두 원자는 α-동치인 `Prop`일 때 같다 |

### 3.2. API

```python
ctx.auto()                                 # 현재 목표를 닫는다
ctx.auto(using=[ctx.thm(em, {P: A})])      # 추가 전제
ctx.auto(limit=100_000)                    # 탐색 단계 한도
```

| 항목         | 정의                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 전제         | 현재 목표의 문맥 가정과 `using`의 `Fact`. `Fact`는 현재 목표의 범위 안에 있어야 한다 (`ScopeError`).        |
| 환경         | 환경의 정리·공리는 자동으로 쓰지 않는다. `classical.em`도 `using`에 인스턴스로 줄 때만 쓴다.              |
| `limit`      | 규칙 적용 횟수의 한도. 기본값 100 000.                                                                    |
| 성공         | 목표를 닫는다. 도출은 기존 전술의 도출과 같은 L0 규칙($\mathrm{Hyp}$, $\land$, $\lor$, $\to$, $\bot\mathrm{E}$)으로만 이루어진다. |

| 실패                                 | 오류와 메시지                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 탐색을 끝까지 마쳤으나 증명이 없음   | `TacticError: auto: not provable in intuitionistic propositional logic from the premises`와 진단 (아래) |
| 한도 초과                            | `TacticError: auto: search limit reached (N steps)`                                               |
| 재생 중 전술 오류                    | `TacticError`. 탐색기 결함 신호로 메시지에 명시한다 (§1 원칙 1)                                    |

**실패 진단.** 원자가 16개 이하이면 고전 진리표로 다음 중 하나를 덧붙인다. 진리표는 결과를 바꾸지 않는 안내이다.

- 전제가 모두 참이고 목표가 거짓인 진리값 배정이 있으면 그 배정 (예: `P = true, Q = false`).
- 그런 배정이 없으면 `classically valid; it may need classical.em` (예: $P \lor \lnot P$).

### 3.3. 탐색

탐색은 시퀀트 $\Gamma \Rightarrow C$ 위에서 G4ip 규칙을 적용한다. $\Gamma$는 순서가 있는 전제 목록이며, 같은 명제는 한 번만 둔다.

**가역 규칙**은 적용할 수 있으면 먼저, 아래 순서대로 적용한다. 가역 규칙은 되돌릴 필요가 없다.

| 규칙                 | 전제에서                       | 결론                                                     |
| -------------------- | ------------------------------ | -------------------------------------------------------- |
| Ax                   | $C \in \Gamma$                 | 닫힘                                                     |
| $\bot$L              | $\bot \in \Gamma$              | 닫힘                                                     |
| $\to$R               | $C = A \to B$                  | $\Gamma, A \Rightarrow B$                                |
| $\land$R             | $C = A \land B$                | $\Gamma \Rightarrow A$, $\Gamma \Rightarrow B$           |
| $\land$L             | $A \land B \in \Gamma$         | $A$, $B$로 바꿈                                          |
| $\lor$L              | $A \lor B \in \Gamma$          | $\Gamma, A \Rightarrow C$, $\Gamma, B \Rightarrow C$     |
| L$\to$원자           | $P \to B$, $P \in \Gamma$ ($P$ 원자) | $P \to B$를 $B$로 바꿈                             |
| L$\to\land$          | $(A \land B) \to D$            | $A \to (B \to D)$로 바꿈                                 |
| L$\to\lor$           | $(A \lor B) \to D$             | $A \to D$, $B \to D$로 바꿈                              |
| L$\to\bot$           | $\bot \to D$                   | 지움 (항상 참이므로 쓸모없다)                            |

**비가역 규칙**은 가역 규칙을 더 적용할 수 없을 때, 다음 후보를 순서대로 시도하고 실패하면 다음 후보로 되돌아간다.

| 규칙             | 조건                       | 전제                                                                    |
| ---------------- | -------------------------- | ----------------------------------------------------------------------- |
| $\lor$R₁, $\lor$R₂ | $C = A \lor B$           | $\Gamma \Rightarrow A$, 다음으로 $\Gamma \Rightarrow B$                  |
| L$\to\to$        | $(A \to B) \to D \in \Gamma$ (전제 순서대로) | $\Gamma', B \to D \Rightarrow A \to B$ 그리고 $\Gamma', D \Rightarrow C$ ($\Gamma'$는 그 함의를 뺀 나머지) |

- 이 규칙들은 축약 없이 종료하며 직관주의 명제 논리에 대해 건전하고 완전하다 (Dyckhoff, *Contraction-free sequent calculi for intuitionistic logic*, JSL 1992). 따라서 탐색이 한도 안에서 끝까지 실패하면, 목표는 전제로부터 명제 규칙만으로 도출되지 않는다.
- 단계 수는 규칙 적용마다 1씩 센다. 같은 입력에 대해 탐색 순서는 결정적이다.
- 구현은 실패한 시퀀트(전제 집합과 목표)를 기억하여 같은 시퀀트를 다시 탐색하지 않는다. 증명의 존재는 전제의 순서와 무관하므로 결과는 바뀌지 않는다.
- 참고 측정 (비규범): `propositional`의 정리 34개를 모두 0.05초에 찾는다. 비둘기집 원리 PHP(5, 4)는 67 656단계, 탐색 0.8초, 재생과 커널 검사를 포함하여 2.8초이다. 따라서 기본 한도 100 000단계는 약 1초의 탐색에 해당한다.

### 3.4. 재생

찾은 증명 트리는 현재 증명 문맥에서 기존 전술로 재생한다. 전제는 `Fact`로 들고 다닌다.

| 규칙                 | 재생                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| Ax                   | `ctx.exact(f)`                                                                                    |
| $\bot$L              | `ctx.exact(ctx.absurd(f, C))`                                                                     |
| $\to$R               | `ctx.intro()`                                                                                     |
| $\land$R             | `ctx.split()` 후 두 목표를 차례로 재생                                                             |
| $\land$L             | `ctx.and_left(f)`, `ctx.and_right(f)`                                                             |
| $\lor$L              | `ctx.cases(f)` 후 두 목표를 차례로 재생                                                            |
| $\lor$R₁, $\lor$R₂   | `ctx.left()`, `ctx.right()`                                                                       |
| L$\to$원자           | `ctx.mp(f, p)`                                                                                    |
| L$\to\land$, L$\to\lor$ | `ctx.have(A → (B → D))` 등으로 새 함의를 만들고, 그 목표를 `intro`와 `mp`, `and_intro`, `or_inl`, `or_inr`로 닫는다 |
| L$\to\bot$           | 아무것도 하지 않는다                                                                              |
| L$\to\to$            | `g = ctx.have(B → D)`(`intro`와 `mp`로 증명), `k = ctx.have(A → B)`(왼쪽 하위 증명을 재생), `ctx.mp(f, k)`로 $D$를 얻고 오른쪽 하위 증명을 재생 |

- 재생은 증명 문맥의 공개 전술만 사용하므로, 결과 도출은 사용자가 손으로 쓴 증명과 같은 방식으로 커널이 검사한다.

### 3.5. 예제

예제는 비규범적이다.

```python
@thy.proof(not_not_em)                     # ⊢ ¬¬(P ∨ ¬P)
def _(ctx):
    ctx.auto()                             # VERIFIED, 공리 없음

@thy.proof(em_goal)                        # ⊢ P ∨ ¬P
def _(ctx):
    ctx.auto()
    # TacticError: auto: not provable in intuitionistic propositional logic from the premises
    #   (classically valid; it may need classical.em)

@thy.proof(peirce)                         # ⊢ ((P → Q) → P) → P
def _(ctx):
    ctx.auto(using=[ctx.thm(em, {P: P})])  # VERIFIED, 의존 공리: classical.em

@thy.proof(all_or)                         # ⊢ (∀x. S(x)) → (∀x. S(x)) ∨ Q
def _(ctx):
    ctx.auto()                             # ∀x. S(x)는 불투명한 원자
```

### 3.6. 범위 밖

- 양화사 규칙(`intro`로 변수 도입, `spec`, `exists`)과 등식 추론은 하지 않는다. 그런 목표는 사용자가 명제적 부분까지 줄인 뒤 `auto`를 쓴다.
- 환경의 정리를 자동으로 고르는 기능(정리 검색)과 고전 모드는 포함하지 않는다.

## 4. 정리 검색

> **상태:** 확정 · 구현됨. 이 절은 현재 목표에 쓸 수 있는 환경의 정리·공리를 찾는 검색과, 이름·명제 문자열로 선언을 찾는 명령을 정의한다. 검색은 증명 상태를 바꾸지 않는다.

### 4.1. 목적

사용자와 이후의 전술 탐색(§6)은 "이 목표를 닫거나 줄일 수 있는 정리가 무엇인가"를 알아야 한다. `ctx.search()`는 환경의 정리 가운데 결론이 현재 목표와 맞는 것을 찾아, 바로 쓸 수 있는 인스턴스 `Fact`와 남는 목표를 돌려준다.

### 4.2. 후보

- 후보는 `ctx.thm`으로 참조할 수 있는 선언, 즉 현재 정리보다 앞에 선언되고 Elaboration된 환경의 정리와 공리이다 ([language-spec.md §5.4](language-spec.md#54-증명-등록)). 문맥의 가정은 후보가 아니다 (가정은 `ctx.auto`가 다룬다).
- 후보 명제를 다음 꼴로 읽는다. $\bar{x}$는 앞쪽의 전칭 변수 가운데 인스턴스화할 것, $B_i$는 전제, $C$는 결론이다. 앞쪽의 $\forall$을 0개, 1개, … 벗긴 각 경우를 모두 시도한다. 0개를 벗기면 $\forall n.\, A$ 꼴의 목표에 정리 전체가 맞을 수 있다.

$$
\forall \bar{x}.\; B_1 \to \dots \to B_n \to C
$$

- 전제 수 $k = 0, 1, \dots, n$ 순서로, $B_{k+1} \to \dots \to C$를 결론으로 보고 맞추기(§4.3)를 시도한다. 처음 성공한 $k$를 쓴다. 이는 `ctx.apply`가 가장 짧은 전제 수를 고르는 규칙과 같다 ([language-spec.md §6.3](language-spec.md#63-목표-전술)). 벗긴 개수가 다른 경우 가운데 남는 목표가 가장 적은 것을 그 후보의 결과로 한다.
- 남는 목표 가운데 현재 목표와 같은 것이 있으면 그 결과는 진전이 없으므로 뺀다 (예: $P \to P$를 $P \mapsto$ 목표로 쓰는 경우).

### 4.3. 맞추기

맞추기는 결론 $C$의 스키마 변수와 전칭 변수 $\bar{x}$에 값을 정하여 $C$가 현재 목표와 α-동치가 되게 한다.

| 결론의 부분                         | 목표의 부분 | 규칙                                                                                                   |
| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| 스키마 원자 $P$                     | 명제 $A$    | $P$가 미정이면 $P \mapsto A$. 이미 정해졌으면 α-동치여야 한다.                                           |
| 스키마 술어 $P(y_1, \dots, y_m)$     | 명제 $A$    | $y_j$가 결론 안의 양화사에 묶인 서로 다른 변수이면 $P \mapsto \lambda y_1 \dots y_m.\, A$ (Miller 패턴). $A$에 다른 묶인 변수가 남으면 실패. $P$가 이미 정해졌으면 적용한 결과가 α-동치여야 한다. 그 밖의 인자 꼴은 지원하지 않는다 (그 후보는 건너뛴다). |
| 전칭 변수 $x_i$ (항 위치)           | 항 $t$      | $x_i$가 미정이면 $x_i \mapsto t$ (종이 같아야 한다). $t$에 결론 안에서 묶인 변수가 있으면 실패.           |
| 그 밖의 연결사, 양화사, 술어, 상수, 등식 | 같은 꼴     | 구조적으로 맞춘다. 양화사의 묶인 변수는 짝지어 비교한다.                                                 |

- 결론에 나타나지 않아 값이 정해지지 않는 전칭 변수나 스키마 변수가 있으면 그 후보는 결과에서 뺀다 (전제에만 나타나는 변수는 사용자가 정해야 하기 때문이다).
- 맞추기는 결정적이며, 실패하면 그 $k$로는 후보가 맞지 않는다.

### 4.4. API

```python
results = ctx.search()                # 현재 목표에 맞는 후보 (최대 10개)
r = results[0]
r.name, r.premises                    # 'arith.add_comm', (남는 목표, …)
ctx.exact(r.fact) if not r.premises else ctx.apply(r.fact)
print(r)                              # arith.add_comm : ctx.spec(ctx.thm(add_comm), m, n)
```

| 항목              | 정의                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| `ctx.search(limit=10)` | 현재 목표에 맞는 후보를 정렬하여 최대 `limit`개 돌려준다. 증명 상태를 바꾸지 않는다.              |
| `SearchResult.name` | 후보의 정규 이름                                                                                     |
| `SearchResult.fact` | 정해진 치환과 항으로 만든 인스턴스 `Fact` (`ctx.thm(decl, subst)`에 `ctx.spec`을 적용한 것). 현재 목표의 범위 안에서 유효하다. |
| `SearchResult.premises` | 남는 목표 $B_1\sigma, \dots, B_k\sigma$. 비어 있으면 `ctx.exact(r.fact)`, 아니면 `ctx.apply(r.fact)`로 쓴다. |
| `SearchResult.axioms` | 후보를 쓰면 더해지는 의존 공리 집합 (공리이면 그 이름, 정리이면 그 정리의 의존 공리)                 |
| `str(r)`          | 이름과, 같은 인스턴스를 만드는 Python 코드의 표시                                                       |

**정렬.** 다음 키의 사전 순서이다. 같은 입력에 대해 결과 순서는 결정적이다.

1. 남는 목표의 수가 적은 것
2. 결론이 구체적인 것 (맞춘 결론이 스키마 원자나 스키마 술어 하나뿐인 후보, 예: $\bot \to P$의 $P$는 어떤 목표에도 맞으므로 뒤에 둔다. `SearchResult.generic`)
3. 비고전적인 것 (의존 공리에 `classical.em`이 없는 것)
4. 의존 공리 수가 적은 것
5. 환경의 선언 순서

### 4.5. 명령행

```bash
axw search FILE.py WORD...      # 이름 또는 명제 표시에 모든 단어가 들어 있는 선언
```

- `FILE.py`의 Theory와 그 가져온 Theory의 정리·공리를 대상으로 한다. 증명 코드를 실행하지 않고 선언만 읽는다 (`thy.check()`를 부르지 않는다).
- 단어는 대소문자를 구분하지 않고, 정규 이름과 `str(statement)`에서 찾는다. 결과는 환경 순서로 `KIND  NAME : STATEMENT`를 한 줄씩 출력한다. 결과가 없으면 종료 코드 1이다.
- README의 예정 명령 `axw search "implication transitivity"`는 이 형식(`axw search FILE.py imp trans`)으로 바꾼다.

### 4.6. 예제

예제는 비규범적이다.

```python
@thy.proof(t)                              # ⊢ ∀m n. m + n = n + m  (arith를 가져옴)
def _(ctx):
    m = ctx.intro()
    n = ctx.intro()
    print(ctx.search()[0])                 # arith.add_comm : ctx.spec(ctx.thm(add_comm), m, n)
    ctx.exact(ctx.search()[0].fact)

@thy.proof(u)                              # h : P → Q, h2 : P ⊢ Q
def _(ctx):
    ...
    r = ctx.search()[0]                    # 예: propositional.mp, 남는 목표 (P → Q, P)
```

### 4.7. 범위 밖

- 다시 쓰기 후보 찾기 (목표 안의 부분 항과 맞는 등식 정리), 전제에서 앞으로 추론하는 검색은 포함하지 않는다.
- 고차 패턴이 아닌 스키마 술어의 맞추기, 의미 기반(임베딩) 검색은 포함하지 않는다.

## 5. 벤치마크

> **상태:** 확정 · 구현됨. 이 절은 자동화의 성능을 재는 고정 문제 집합, 기준 풀이기(solver), 측정 도구 `axw bench`를 정의한다. 이후의 전술 탐색(§6)은 이 벤치마크로 평가한다.

### 5.1. 목적과 원칙

- 같은 문제 집합에 대해 풀이기의 성공률, 시간, 증명 크기를 재고 비교한다.
- **성공은 커널 검사로만 센다.** 풀이기가 목표를 닫았더라도 커널이 `VERIFIED`로 판정한 경우에만 성공이다.
- **문제는 검증되어 있어야 한다.** 증명 가능한 문제는 참조 증명을 함께 두며, 테스트는 모든 참조 증명이 `VERIFIED`인지 확인한다. 직관주의적으로 증명할 수 없는 문제는 그 사실을 기대값으로 기록한다.
- **결과는 시간을 빼면 결정적이다.**

### 5.2. 문제

문제는 패키지 `axiomweave.bench.problems`의 모듈에 Python 값으로 둔다 (`axw bench`가 설치 위치와 관계없이 찾을 수 있도록 패키지 안에 둔다).

```python
Problem(
    name="prop.curry",                 # 범주.이름, 유일
    category="propositional",          # "propositional" | "first_order" | "arithmetic"
    imports=(),                        # 문제 Theory가 가져오는 표준 Theory
    statement=lambda: ((P & Q) >> R) >> (P >> (Q >> R)),
    expected="provable",               # "provable" | "unprovable"
    reference=_curry_proof,            # provable이면 필수: ctx -> None (어떤 전술이든 쓸 수 있다)
    note="",
)
```

| 항목         | 정의                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| `statement`  | 문제 명제를 만드는 함수. 종·상수가 필요하면 문제 모듈의 Theory에서 선언한다 (§5.4 문제 Theory).            |
| `imports`    | `arith`, `propositional`, `classical` 등. 가져온 Theory에 문제와 같은 명제(α-동치)의 정리가 있으면 안 된다 (검색만으로 풀리는 문제를 피한다). 테스트가 확인한다. |
| `expected`   | `"unprovable"`은 가져온 Theory와 직관주의 논리로 증명할 수 없음이 알려진 문제이다 (예: $P \lor \lnot P$, 술꾼 역설). 이런 문제가 `VERIFIED`가 되면 결함 신호이다. |

**v0.1 문제 집합 (60문제, provable 51 · unprovable 9).**

| 범주          | 수   | 예                                                                                                 |
| ------------- | ---- | -------------------------------------------------------------------------------------------------- |
| `propositional` | 25 (20 · 5) | 커링, 분배, 이중 부정 법칙, 드모르간의 직관주의 방향, 비둘기집 PHP(3,2)·(4,3); 증명 불가: 배중률, 이중 부정 제거, 퍼스, Gödel–Dummett $(P\to Q)\lor(Q\to P)$ |
| `first_order` | 15 (13 · 2) | 양화사 교환 $\forall\forall$, $\exists\forall \to \forall\exists$, $\forall$과 $\land$의 분배, 등식의 대칭·추이·합동; 증명 불가: 술꾼 역설, $\lnot\forall \to \exists\lnot$ |
| `arithmetic`  | 20 (18 · 2) | $2 + 2 = 4$, $(n+1)^2$·$(n+1)^3$ 전개, $n \ne S(n)$, $1 \ne 2$, 덧셈 소거, $m + n = 0 \to m = 0$, 라이브러리에 없는 가환 반환 항등식; 증명 불가(거짓): $\forall n.\, n + 1 = n$, $\exists n.\, S(n) = 0$ |

### 5.3. 풀이기

풀이기는 증명 함수와 같은 꼴(`ctx -> None`)의 함수이며 이름으로 등록한다. v0.1의 기준 풀이기는 다음과 같다.

| 이름        | 동작                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| `auto`      | `ctx.auto()`                                                                                             |
| `search`    | 앞쪽의 $\forall$·$\to$를 `intro`한 뒤, 남는 목표가 없는 첫 `ctx.search()` 결과로 `exact`                   |
| `ring`      | 앞쪽의 $\forall$을 `intro`한 뒤 `ctx.ring()`                                                              |
| `portfolio` | `auto`, `search`, `ring`을 차례로 시도하여 처음 `VERIFIED`가 된 결과를 쓴다                                |

- 각 시도는 새 문제 Theory에서 따로 검사한다. 따라서 실패한 시도가 다음 시도의 증명 상태에 영향을 주지 않는다.
- 풀이기는 자체 한도(`auto`의 단계 한도, `ring`의 크기 한도)로 끝난다. v0.1은 강제 시간 제한(프로세스 중단)을 두지 않는다.

### 5.4. 측정

한 문제와 한 풀이기마다 다음을 기록한다.

| 항목       | 정의                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| `status`   | 문제 정리의 검증 상태 (`VERIFIED`, `REJECTED`, `UNPROVEN`)                                  |
| `seconds`  | 풀이기 실행, Elaboration, 커널 검사를 포함한 벽시계 시간                                    |
| `nodes`    | 인증서에서 문제 정리의 도출 노드 수 (`VERIFIED`일 때)                                       |
| `axioms`   | 문제 정리의 의존 공리                                                                      |
| `error`    | 실패한 경우 진단의 첫 줄                                                                    |
| `via`      | `portfolio`에서 성공한 풀이기의 이름                                                        |

- 문제 Theory는 `bench.<범주>` 이름공간에 문제마다 새로 만든다. 문제 모듈이 선언한 종·상수가 있으면 그 Theory를 가져온다.
- 요약은 범주별 `해결 수 / provable 문제 수`, 총 시간, 그리고 `unprovable` 문제가 `VERIFIED`가 된 경우의 경보이다.

### 5.5. 명령행

```bash
axw bench                                  # 모든 풀이기, 모든 문제
axw bench --solver auto --solver ring      # 풀이기 선택
axw bench --category arithmetic            # 범주 선택
axw bench --json results.json              # 결과를 JSON으로도 저장
axw bench --check-references               # 문제 집합 자체를 참조 증명으로 검증
```

| 상황                                                         | 종료 코드 |
| ------------------------------------------------------------ | --------- |
| 실행 완료                                                    | 0         |
| `unprovable` 문제가 `VERIFIED`가 됨, 또는 참조 증명이 실패함 | 1         |
| 사용법 오류 (모르는 풀이기·범주)                             | 2         |

- 표 출력은 문제마다 한 줄(`문제  풀이기별 상태와 시간`)과 범주별 요약이다. JSON은 레코드의 목록이며 각 레코드는 `solver`, `problem`, `category`, `expected`와 §5.4의 항목을 갖는다. `--check-references`의 레코드는 풀이기 이름이 `reference`이다.

**기준 결과** (비규범, 2026-11-28 측정, 60문제 × 풀이기 4개, 총 11.7초)

| 범주 (provable 수) | `auto` | `search` | `ring` | `portfolio` |
| ------------------ | ------ | -------- | ------ | ----------- |
| `propositional` (20) | 20 | 0 | 0 | 20 |
| `first_order` (13)   | 0  | 0 | 0 | 0  |
| `arithmetic` (18)    | 0  | 2 | 13 | 13 |

- `unprovable` 문제 9개는 어느 풀이기로도 `VERIFIED`가 되지 않았다 (경보 없음).
- 일차 문제는 양화사의 도입·제거가 필요하므로 기준 풀이기로는 풀리지 않는다. 산술의 남은 5문제는 귀납이나 단사성이 필요하다. 이 두 부분이 전술 탐색(§6)의 첫 평가 대상이다.


### 5.6. 범위 밖

- 외부 벤치마크 형식(TPTP, ILTP) 가져오기, 강제 시간 제한, 병렬 실행, 결과의 시간 추이 저장은 포함하지 않는다.
- 기계 학습 정책과 전술 탐색 루프는 §6에서 다룬다.

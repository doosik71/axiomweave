# AxiomWeave 자동화 명세 (AxiomAI Specification)

> **문서 상태:** 초안(Draft) · §3 개정안 검토 대기  
> 상위 문서: [specification.md](specification.md). 이 문서는 증명을 자동으로 찾는 계층(AxiomAI)을 정의한다. 첫 대상은 명제 논리 결정 절차 `ctx.auto()`(§3)이다. 규범적 표현은 [specification.md §1.1](specification.md#11-규범적-표현)을 따른다.

## 1. 범위와 원칙

| 포함                                                   | 제외 (이후 개정)                                            |
| ------------------------------------------------------ | ----------------------------------------------------------- |
| 직관주의 명제 논리의 완전한 결정 절차 (§3)             | 정리 검색, 전술 탐색 루프, 기계 학습 정책, 벤치마크 (§4)    |
| 찾은 증명을 기존 전술로 재생하여 도출을 만드는 방법    | 양화사·등식 추론의 자동화                                   |

다음 원칙은 이 문서의 모든 자동화에 적용한다.

1. **자동화는 비신뢰 계층이다.** 탐색기는 증명을 직접 승인하지 않는다. 찾은 증명은 기존 전술로 재생되어 일반 도출이 되고, 커널이 검사한다. 새 커널 규칙이나 공리를 추가하지 않는다.
2. **실패는 거짓이 아니다.** 탐색 실패나 한도 초과는 명제가 거짓임을 뜻하지 않는다 ([specification.md §6](specification.md#6-검증-상태)). 완전한 결정 절차가 탐색을 끝까지 마친 경우에만, 그 절차가 다루는 규칙의 범위 안에서 "도출되지 않는다"고 보고할 수 있다.
3. **결정성.** 같은 증명 상태와 같은 한도에 대해 같은 결과와 같은 도출을 만들어야 한다.
4. **한도.** 모든 탐색은 단계 수 한도를 가져야 하며, 한도 초과는 실패와 구별하여 보고한다.

## 2. 설계 결정 요약

| 항목            | 결정                                                                                         | 근거                                                    |
| --------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 첫 절차         | Dyckhoff의 G4ip(LJT) 시퀀트 계산                                                             | 축약(contraction) 없이 종료하며 직관주의 명제 논리에 완전하다. |
| 대상 논리       | 목표의 명제 골격. 양화사, 등식, 술어 적용은 불투명한 원자로 본다                              | L1·L2 목표의 명제적 부분도 다룰 수 있다.                 |
| 증명 생성       | 탐색은 순수 시퀀트 위에서 하고, 찾은 증명 트리를 기존 전술로 재생한다                          | 되돌리기(backtracking)가 증명 상태를 건드리지 않는다.    |
| 외부 의존성     | 없음                                                                                         | 표준 기능으로 항상 쓸 수 있어야 한다.                   |

## 3. 명제 논리 결정 절차 (개정안)

> **상태:** 개정안(Proposed) · 검토 대기.

### 3.1. 대상

목표와 전제를 명제 골격으로 읽는다.

| 명제                                                         | 골격                                           |
| ------------------------------------------------------------ | ---------------------------------------------- |
| $\bot$, $A \land B$, $A \lor B$, $A \to B$                   | 그대로 ($\lnot A$는 $A \to \bot$, $A \leftrightarrow B$는 두 함의의 논리곱) |
| 원자 $P$, 스키마 술어, 술어 적용, 등식, $\forall$, $\exists$ | 불투명한 원자. 두 원자는 α-동치인 `Prop`일 때 같다 |

### 3.2. API

```python
ctx.auto()                                 # 현재 목표를 닫는다
ctx.auto(using=[ctx.thm(em, {P: A})])      # 추가 전제
ctx.auto(limit=100_000)                    # 탐색 단계 한도
```

| 항목         | 정의                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 전제         | 현재 목표의 문맥 가정과 `using`의 `Fact`. `Fact`는 현재 목표의 범위 안에 있어야 한다 (`ScopeError`).        |
| 환경         | 환경의 정리·공리는 자동으로 쓰지 않는다. `classical.em`도 `using`에 인스턴스로 줄 때만 쓴다.              |
| `limit`      | 규칙 적용 횟수의 한도. 기본값 100 000.                                                                    |
| 성공         | 목표를 닫는다. 도출은 기존 전술의 도출과 같은 L0 규칙($\mathrm{Hyp}$, $\land$, $\lor$, $\to$, $\bot\mathrm{E}$)으로만 이루어진다. |

| 실패                                 | 오류와 메시지                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 탐색을 끝까지 마쳤으나 증명이 없음   | `TacticError: auto: not provable in intuitionistic propositional logic from the premises`와 진단 (아래) |
| 한도 초과                            | `TacticError: auto: search limit reached (N steps)`                                               |
| 재생 중 전술 오류                    | `TacticError`. 탐색기 결함 신호로 메시지에 명시한다 (§1 원칙 1)                                    |

**실패 진단.** 원자가 16개 이하이면 고전 진리표로 다음 중 하나를 덧붙인다. 진리표는 결과를 바꾸지 않는 안내이다.

- 전제가 모두 참이고 목표가 거짓인 진리값 배정이 있으면 그 배정 (예: `P = true, Q = false`).
- 그런 배정이 없으면 `classically valid; it may need classical.em` (예: $P \lor \lnot P$).

### 3.3. 탐색

탐색은 시퀀트 $\Gamma \Rightarrow C$ 위에서 G4ip 규칙을 적용한다. $\Gamma$는 순서가 있는 전제 목록이며, 같은 명제는 한 번만 둔다.

**가역 규칙**은 적용할 수 있으면 먼저, 아래 순서대로 적용한다. 가역 규칙은 되돌릴 필요가 없다.

| 규칙                 | 전제에서                       | 결론                                                     |
| -------------------- | ------------------------------ | -------------------------------------------------------- |
| Ax                   | $C \in \Gamma$                 | 닫힘                                                     |
| $\bot$L              | $\bot \in \Gamma$              | 닫힘                                                     |
| $\to$R               | $C = A \to B$                  | $\Gamma, A \Rightarrow B$                                |
| $\land$R             | $C = A \land B$                | $\Gamma \Rightarrow A$, $\Gamma \Rightarrow B$           |
| $\land$L             | $A \land B \in \Gamma$         | $A$, $B$로 바꿈                                          |
| $\lor$L              | $A \lor B \in \Gamma$          | $\Gamma, A \Rightarrow C$, $\Gamma, B \Rightarrow C$     |
| L$\to$원자           | $P \to B$, $P \in \Gamma$ ($P$ 원자) | $P \to B$를 $B$로 바꿈                             |
| L$\to\land$          | $(A \land B) \to D$            | $A \to (B \to D)$로 바꿈                                 |
| L$\to\lor$           | $(A \lor B) \to D$             | $A \to D$, $B \to D$로 바꿈                              |
| L$\to\bot$           | $\bot \to D$                   | 지움 (항상 참이므로 쓸모없다)                            |

**비가역 규칙**은 가역 규칙을 더 적용할 수 없을 때, 다음 후보를 순서대로 시도하고 실패하면 다음 후보로 되돌아간다.

| 규칙             | 조건                       | 전제                                                                    |
| ---------------- | -------------------------- | ----------------------------------------------------------------------- |
| $\lor$R₁, $\lor$R₂ | $C = A \lor B$           | $\Gamma \Rightarrow A$, 다음으로 $\Gamma \Rightarrow B$                  |
| L$\to\to$        | $(A \to B) \to D \in \Gamma$ (전제 순서대로) | $\Gamma', B \to D \Rightarrow A \to B$ 그리고 $\Gamma', D \Rightarrow C$ ($\Gamma'$는 그 함의를 뺀 나머지) |

- 이 규칙들은 축약 없이 종료하며 직관주의 명제 논리에 대해 건전하고 완전하다 (Dyckhoff, *Contraction-free sequent calculi for intuitionistic logic*, JSL 1992). 따라서 탐색이 한도 안에서 끝까지 실패하면, 목표는 전제로부터 명제 규칙만으로 도출되지 않는다.
- 단계 수는 규칙 적용마다 1씩 센다. 같은 입력에 대해 탐색 순서는 결정적이다.

### 3.4. 재생

찾은 증명 트리는 현재 증명 문맥에서 기존 전술로 재생한다. 전제는 `Fact`로 들고 다닌다.

| 규칙                 | 재생                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| Ax                   | `ctx.exact(f)`                                                                                    |
| $\bot$L              | `ctx.exact(ctx.absurd(f, C))`                                                                     |
| $\to$R               | `ctx.intro()`                                                                                     |
| $\land$R             | `ctx.split()` 후 두 목표를 차례로 재생                                                             |
| $\land$L             | `ctx.and_left(f)`, `ctx.and_right(f)`                                                             |
| $\lor$L              | `ctx.cases(f)` 후 두 목표를 차례로 재생                                                            |
| $\lor$R₁, $\lor$R₂   | `ctx.left()`, `ctx.right()`                                                                       |
| L$\to$원자           | `ctx.mp(f, p)`                                                                                    |
| L$\to\land$, L$\to\lor$ | `ctx.have(A → (B → D))` 등으로 새 함의를 만들고, 그 목표를 `intro`와 `mp`, `and_intro`, `or_inl`, `or_inr`로 닫는다 |
| L$\to\bot$           | 아무것도 하지 않는다                                                                              |
| L$\to\to$            | `g = ctx.have(B → D)`(`intro`와 `mp`로 증명), `k = ctx.have(A → B)`(왼쪽 하위 증명을 재생), `ctx.mp(f, k)`로 $D$를 얻고 오른쪽 하위 증명을 재생 |

- 재생은 증명 문맥의 공개 전술만 사용하므로, 결과 도출은 사용자가 손으로 쓴 증명과 같은 방식으로 커널이 검사한다.

### 3.5. 예제

예제는 비규범적이다.

```python
@thy.proof(not_not_em)                     # ⊢ ¬¬(P ∨ ¬P)
def _(ctx):
    ctx.auto()                             # VERIFIED, 공리 없음

@thy.proof(em_goal)                        # ⊢ P ∨ ¬P
def _(ctx):
    ctx.auto()
    # TacticError: auto: not provable in intuitionistic propositional logic from the premises
    #   (classically valid; it may need classical.em)

@thy.proof(peirce)                         # ⊢ ((P → Q) → P) → P
def _(ctx):
    ctx.auto(using=[ctx.thm(em, {P: P})])  # VERIFIED, 의존 공리: classical.em

@thy.proof(all_or)                         # ⊢ (∀x. S(x)) → (∀x. S(x)) ∨ Q
def _(ctx):
    ctx.auto()                             # ∀x. S(x)는 불투명한 원자
```

### 3.6. 범위 밖

- 양화사 규칙(`intro`로 변수 도입, `spec`, `exists`)과 등식 추론은 하지 않는다. 그런 목표는 사용자가 명제적 부분까지 줄인 뒤 `auto`를 쓴다.
- 환경의 정리를 자동으로 고르는 기능(정리 검색)과 고전 모드는 포함하지 않는다.

## 4. 이후 계획 (비규범)

- **정리 검색:** 현재 목표에 적용하거나 인스턴스화할 수 있는 환경의 정리를 찾는다 (`axw search`, `ctx.search`).
- **전술 탐색:** 기존 전술(`intro`, `split`, `cases`, `apply`, `ring`, `induction`, `auto`)을 조합하는 탐색 루프와 정책.
- **벤치마크:** 명제·일차·산술 문제 집합과 채점 도구.

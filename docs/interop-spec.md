# AxiomWeave 상호운용 명세 (Interoperability Specification)

> **문서 상태:** 초안(Draft) · §3 확정 · 구현됨 (`axiomweave.backends.lean`, `axw export-lean`), Lean 4.34.1로 교차 검증됨 (§3.7) · §4 확정 · 구현됨 (`axiomweave.backends.smt`, `ctx.counterexample`) · §5 확정 · 구현됨 (`ctx.ring`, `axiomweave.language.ring`, `axiomweave.backends.symbolic`)  
> 상위 문서: [specification.md](specification.md). 이 문서는 AxiomWeave와 외부 정리 증명 시스템·도구 사이의 변환을 정의한다. 첫 대상은 검증된 인증서를 Lean 4 소스로 내보내는 교차 검증(§3)이고, 다음은 SMT 솔버로 증명할 수 없는 목표의 반례를 찾는 것(§4)과 SymPy로 판정한 다항식 등식을 증명으로 재구성하는 것(§5)이다. 규범적 표현은 [specification.md §1.1](specification.md#11-규범적-표현)을 따른다.

## 1. 범위와 원칙

| 포함                                                       | 제외 (이후 개정)                                                |
| ---------------------------------------------------------- | --------------------------------------------------------------- |
| 커널이 수락한 인증서(L0–L2, L3 산술)의 Lean 4 소스 변환    | Lean 증명이나 정리를 AxiomWeave로 가져오기 (`EXTERNAL_VERIFIED`) |
| 변환 결과를 Lean으로 다시 검사하는 교차 검증 절차          | SMT 응답의 증명 재구성, SymPy 후보 생성                         |
| Z3 반례 탐색 (§4)                                          |                                                                 |
| SymPy 다항식 등식 판정과 증명 재구성 (§5)                  |                                                                 |
| 표준 공리의 Lean 대응과 그 증명                            | Mathlib 의존, Lean 외 시스템(Rocq, Isabelle)                    |

다음 원칙은 이 문서의 모든 연계에 적용한다.

1. **커널이 기준이다.** 외부 시스템의 결과는 정리의 상태를 바꾸지 않는다. Lean 교차 검증의 성공은 `VERIFIED`를 대신하지 않고, 실패는 `VERIFIED`를 취소하지 않는다 ([specification.md §6](specification.md#6-검증-상태)).
2. **변환기는 비신뢰 계층이다.** 변환기는 커널 밖의 도구이며, 신뢰 기반([specification.md §5.4](specification.md#54-신뢰-기반))에 포함되지 않는다. 커널은 변환기나 외부 시스템을 호출해서는 안 된다.
3. **입력은 인증서이다.** 변환은 Python 증명 코드가 아니라 커널이 수락한 인증서(`.axwp`)에서 시작한다. 따라서 교차 검증의 대상은 커널이 실제로 검사한 증명 객체이다.
4. **불일치는 결함 신호이다.** 커널이 수락한 정리를 Lean이 거부하면 커널, 변환기, 또는 표준 공리 대응 중 하나에 결함이 있다는 뜻이다. 이는 조사 대상이며 자동으로 해소해서는 안 된다.

## 2. 설계 결정 요약

| 항목              | 결정                                                                                                       | 근거                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 대상              | Lean 4 코어만 사용한다. Mathlib에 의존하지 않는다.                                                         | 설치 부담과 버전 변동을 줄인다.                                    |
| 변환 단위         | 인증서 하나를 Lean 파일 하나로 변환한다. 커널이 수락한 선언만 포함한다.                                     | 자기완결 번들([kernel-spec.md §6.2](kernel-spec.md#62-자기완결성))과 대응한다. |
| 증명 변환         | 도출 트리의 각 노드를 명시적 Lean 항으로 옮긴다. 모든 암묵 인자를 `@`로 채운다.                             | Lean의 추론(elaboration)에 의존하지 않아 불일치의 원인이 분명하다. |
| 스키마 변수       | 정리와 공리의 스키마 변수는 Lean 정리의 명시적 매개변수가 된다.                                             | $\mathrm{Thm}$/$\mathrm{Ax}$ 인스턴스화가 함수 적용이 된다.        |
| 종·상수·사용자 공리 | Lean `axiom` 선언으로 옮긴다.                                                                             | 의미를 고정하지 않는 선언이라는 점이 같다.                          |
| 표준 공리         | Lean 코어의 정의로 **증명**한다 (`classical.em`, `arith.*`).                                               | 표준 공리가 Lean의 표준 의미에서 참임을 함께 검사한다.             |
| 결과의 지위       | 교차 검증 결과는 보고서에만 기록한다. 검증 상태와 의존 공리 집합은 바뀌지 않는다.                           | 원칙 1.                                                            |

## 3. Lean 4 내보내기

### 3.1. 입력과 전제

- 변환기는 인증서를 먼저 커널(`check_bundle`)로 검증해야 한다. 허용 정책은 `axw verify`와 같다 ([kernel-spec.md §9.3](kernel-spec.md#93-언어-계층과의-연결)).
- 커널이 거부한 번들은 내보내지 않는다. 번들 단계는 통과했으나 일부 선언이 거부된 경우, 수락된 선언(`ACCEPTED`, `VERIFIED`)만 내보내고 거부된 선언의 이름을 보고한다. 거부된 정리를 참조하는 정리는 커널이 이미 거부하므로 함께 빠진다.
- 변환기는 증명 노드의 명시적 인자를 채우기 위해 커널과 같은 방식으로 각 노드의 결론을 재계산한다. 이 재계산은 변환기 안의 비신뢰 계산이며, 그 정확성은 Lean 검사로 드러난다.

### 3.2. 파일 구조

```lean
-- Generated by AxiomWeave <version> from <theory> (bundle <bundle_hash>)
-- Lean 4 core only. This file is a cross-check, not a source of truth.
set_option autoImplicit false

<표준 대응 정의와 정리>   -- §3.6, 사용된 경우에만
<선언들>                   -- 번들의 순서대로
```

- 선언은 번들의 순서대로 하나씩 내보낸다.
- 출력은 같은 인증서와 같은 변환기 버전에 대해 바이트 단위로 결정적이어야 한다.

### 3.3. 이름

| 대상                          | Lean 표기                                                                        |
| ----------------------------- | -------------------------------------------------------------------------------- |
| 선언 이름 `a.b.c`             | 각 성분을 `«…»`로 감싼 `«a».«b».«c»`                                             |
| 스키마 변수 `P`               | `«P»`                                                                            |
| 가정 이름 `h`                 | `«h_h»` (가정 이름에 `h_` 접두사. 생성된 변수 이름 `x0`, `x1`, …과 겹치지 않는다)                                        |
| 속박 변수 (de Bruijn)         | 바인더가 놓인 깊이 $d$ (바깥에서 0부터)에 따라 `x0`, `x1`, …                      |

- 모든 이름 성분을 `«…»`로 감싸므로 Lean 예약어(`at`, `fun`, `example` 등)와 충돌하지 않는다.
- 선언은 루트 이름공간에 둔다. `arith.Nat` 같은 이름은 `«arith».«Nat»`이며 Lean의 `Nat`과 다른 이름이다 (표준 대응은 §3.6에서 정의로 연결한다).
- 스키마 변수 이름이 `x0`처럼 생성된 이름과 같으면 Lean에서 가려질(shadowing) 수 있다. 이 경우 Lean이 파일을 거부할 수는 있으나 잘못된 증명을 수락하지는 않는다. Lean은 내보낸 명제 자체에 대해 증명을 검사하기 때문이다.

### 3.4. 명제와 항

| AxiomWeave                       | Lean 4                                   |
| -------------------------------- | ---------------------------------------- |
| $\bot$                           | `False`                                  |
| $A \land B$                      | `(A ∧ B)`                                |
| $A \lor B$                       | `(A ∨ B)`                                |
| $A \to B$                        | `(A → B)`                                |
| 원자 $P$, 스키마 술어 $P(t_1, …)$ | `«P»`, `(«P» t₁ …)`                     |
| 술어 기호 $p(t_1, …)$, 함수 기호 $f(t_1, …)$ | `(p t₁ …)`, `(f t₁ …)`, 인자가 없으면 `p`, `f` |
| $\forall x{:}S.\, A$             | `(∀ (xd : S), A)`                        |
| $\exists x{:}S.\, A$             | `(∃ (xd : S), A)`                        |
| $t =_S u$                        | `(@Eq S t u)`                            |

- 축약 표기는 커널 입력에 없으므로 내보내지 않는다. $\lnot A$는 `(A → False)`로 나타난다.
- 모든 복합 명제와 적용을 괄호로 감싼다. 연산자 우선순위에 의존하지 않는다.

### 3.5. 선언과 증명

**선언**

| 인증서 선언                         | Lean                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------ |
| `sort S`                            | `axiom S : Type`                                                                     |
| `const c : S₁ → … → ρ`              | `axiom c : S₁ → … → ρ'` ($\rho' $는 종 또는 `Prop`)                                  |
| `axiom n : A` (사용자)              | `axiom n (P₁ : τ₁) … : A`                                                            |
| `theorem n : A` (증명 $D$)          | `theorem n (P₁ : τ₁) … : A := ⟦D⟧`                                                    |

- 매개변수 $P_i$는 명제의 스키마 변수이며, 명제에 처음 나타나는 순서로 나열한다. 타입 $\tau_i$는 인자가 없으면 `Prop`, 있으면 `S₁ → … → Prop`이다.
- 표준 공리는 §3.6의 대응을 쓰며 `axiom`으로 내보내지 않는다.

**증명 노드** ($\llbracket\cdot\rrbracket$, 각 노드의 결론과 전제 명제는 §3.1의 재계산으로 얻는다)

| 노드                                   | Lean 항                                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `hyp h`                                | `«h_h»`                                                                                          |
| `and_i` ($A$, $B$)                     | `(@And.intro A B ⟦left⟧ ⟦right⟧)`                                                                 |
| `and_e1`, `and_e2` ($A \land B$)       | `(@And.left A B ⟦of⟧)`, `(@And.right A B ⟦of⟧)`                                                   |
| `or_i1`, `or_i2` ($A \lor B$)          | `(@Or.inl A B ⟦of⟧)`, `(@Or.inr A B ⟦of⟧)`                                                        |
| `or_e` ($A \lor B$, 결론 $C$)          | `(@Or.elim A B C ⟦of⟧ (fun («h_h₁» : A) => ⟦left⟧) (fun («h_h₂» : B) => ⟦right⟧))`                |
| `imp_i h : A`                          | `(fun («h_h» : A) => ⟦body⟧)`                                                                     |
| `imp_e`                                | `(⟦fn⟧ ⟦arg⟧)`                                                                                    |
| `false_e` (결론 $A$)                   | `(@False.elim A ⟦of⟧)`                                                                            |
| `all_i S`                              | `(fun (xd : S) => ⟦body⟧)`                                                                        |
| `all_e t`                              | `(⟦of⟧ t)`                                                                                        |
| `ex_i` ($S$, $\lambda x.\, A$, $t$)    | `(@Exists.intro S (fun (xd : S) => A) t ⟦of⟧)`                                                    |
| `ex_e h` ($S$, $\lambda x.\, A$, 결론 $C$) | `(@Exists.elim S (fun (xd : S) => A) C ⟦of⟧ (fun (xd : S) («h_h» : A) => ⟦body⟧))`          |
| `eq_refl t` ($S$)                      | `(@rfl S t)`                                                                                      |
| `eq_e` ($t =_S u$, 동기 $\lambda x.\, M$) | `(@Eq.subst S (fun (xd : S) => M) t u ⟦eq⟧ ⟦of⟧)`                                             |
| `thm n σ`, `ax n σ`                    | `(n a₁ …)`: $a_i$는 $n$의 매개변수 $P_i$에 대한 $\sigma(P_i)$                                      |

- `xd`는 그 바인더의 깊이에 따른 이름이다 (§3.3).
- `thm`/`ax`의 치환 값은 인자가 없으면 명제, 있으면 `(fun (xd : S₁) … => B)`이다. 치환에 없는 스키마 변수 $P_i$는 그대로 전달한다. 그 $P_i$가 현재 정리의 매개변수가 아니면 (증명 안에서만 나타나는 스키마 변수), 증명 전체에서 일관되게 `True` (인자가 있으면 `fun … => True`)로 대체한다. 도출은 균일 치환에 대해 닫혀 있으므로 이 대체는 증명의 타당성을 바꾸지 않는다 ([logic-spec.md §10](logic-spec.md#10-메타-성질)).

### 3.6. 표준 공리의 Lean 대응

표준 허용 목록의 공리([kernel-spec.md §9.2](kernel-spec.md#92-표준-정책))는 `axiom`이 아니라 Lean 코어로 증명한 정리로 내보낸다.

| AxiomWeave                     | Lean 대응                                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| `classical.em`                 | `theorem «classical».«em» («P» : Prop) : («P» ∨ («P» → False)) := Classical.em «P»`            |
| `sort arith.Nat`               | `abbrev «arith».«Nat» : Type := Nat`                                                           |
| `const arith.zero`, `succ`, `add`, `mul` | `Nat.zero`, `Nat.succ`, `Nat.add`, `Nat.mul`로 정의한 `def` (`abbrev`)              |
| `arith.*` 공리 7개             | 위 정의 아래에서 Lean 코어로 증명한 `theorem`. 증명 항은 변환기가 정하며, 대상 Lean 버전에서 검사되어야 한다. |

- 수락된 `arith.*` 표준 공리가 번들에 하나라도 있으면 `arith.Nat`과 네 상수는 `axiom`이 아니라 위 정의로 내보낸다. 번들의 해당 `sort`/`const` 선언은 인자·결과 종이 표준과 같을 때만 이 정의로 대체된다.
- 표준 공리의 명제는 다른 선언과 같이 번들에서 변환하고, 증명 항만 고정 텍스트를 쓴다. 커널이 공리의 해시를 허용 목록과 대조했으므로 명제는 표준과 같다.
- 선언은 그 이름의 이름공간 안에서 elaboration되므로, 고정 텍스트는 Lean 코어 이름을 `_root_.Nat`, `_root_.Classical.em`처럼 루트에서 지정한다.
- 표준 공리의 대응은 변환기에 내장된 고정 텍스트이다. 대응 텍스트를 바꾸면 변환기 버전을 올린다.
- 이 대응이 Lean에서 검사된다는 것은, 표준 공리가 Lean이 정의한 자연수와 고전 논리에서 참이라는 독립적인 근거가 된다.

### 3.7. 교차 검증 절차

1. `axw export-lean <file.axwp> -o <file.lean>`: 커널 검증 후 Lean 파일을 쓴다 (§3.1).
2. `axw export-lean <file.axwp> -o <file.lean> --check`: 추가로 `lean <file.lean>`을 실행한다. `lean` 실행 파일이 없으면 검사를 건너뛰었다고 보고하고 종료 코드 0이 아닌 별도 코드(3)를 반환한다.
3. 보고서는 커널 결과, 내보낸 선언 수, Lean 검사 결과(성공·실패·건너뜀)와 Lean 버전(`lean --version`)을 포함한다.

| 상황                                   | 종료 코드 |
| -------------------------------------- | --------- |
| 내보내기 성공 (Lean 검사를 요청하지 않음) 또는 Lean 검사 성공 | 0 |
| 커널이 번들을 거부함, 또는 Lean이 파일을 거부함 | 1      |
| 사용법 오류                            | 2         |
| `--check`를 요청했으나 `lean`이 없음    | 3         |

- 번들 단계는 통과했으나 일부 선언이 거부되면 수락된 선언으로 파일을 쓰고, 거부된 선언을 보고한 뒤 종료 코드 1을 반환한다. 이때 Lean 검사는 실행하지 않는다.

- 교차 검증 결과는 인증서에 기록하지 않는다.
- 테스트는 `lean`이 설치된 환경에서만 Lean 검사를 실행하고, 그렇지 않으면 생성 결과의 구조만 검사한다.
- **검증 현황:** 2026-11-28, `leanprover/lean4:v4.34.1`(Windows x86_64)로 §3.9의 대상 7개를 모두 검사하였다. 모든 파일이 오류와 경고 없이 통과했으며 (각 약 1–1.5초), 변환기와 §3.6의 고정 증명 항은 바꿀 필요가 없었다.

  | 대상 | 결과 |
  | ---- | ---- |
  | `implication`, `first_order`, `equality` 예제 | 통과 |
  | `propositional` (정리 34개) | 통과 |
  | `arith` (표준 공리 7개를 Lean `Nat`으로 증명, 정리 15개) | 통과 |
  | `classical` (`Classical.em` 대응, `dne`, `peirce`) | 통과 |
  | `ctx.ring()`으로 증명한 $(m+n)^2$ 전개 | 통과 |

  음성 대조로, 증명 단계·정리 명제·`arith.add`의 정의를 일부러 바꾼 파일은 Lean이 모두 거부함을 확인하였다. Lean이 설치된 환경에서는 테스트가 같은 대상과 음성 대조를 검사한다.

### 3.8. 예제

예제는 비규범적이다. language-spec §11.1의 함의 추이성 정리와 logic-spec §12.12 (1)의 정리는 다음과 같이 내보내진다.


## 4. SMT 반례 탐색

> **상태:** 확정 · 구현됨. 이 절은 Z3로 증명할 수 없는 목표를 설명하는 반례 탐색을 정의한다. 탐색 결과는 증명이 아니며, 검증 상태와 인증서에 영향을 주지 않는다 (§1 원칙 1–2).

### 4.1. 목적과 지위

반례 탐색은 열린 목표 $\Gamma \vdash A$에 대해, 문맥의 모든 가정이 참이고 $A$가 거짓인 고전 다종(many-sorted) 구조 $M$을 찾는다. 사용자와 자동화 도구는 이를 통해 "이 목표는 지금의 가정으로는 증명할 수 없다"는 사실과 그 이유를 확인한다.

| 결과 (`status`) | 의미                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `found`         | 반례 모델 $M$을 찾았다. 아래 근거에 따라 목표는 주어진 전제로부터 도출되지 않는다.              |
| `none`          | 인코딩 안에서 반례가 없다. 목표가 고전적으로 참이라는 뜻일 뿐, **증명 가능하다는 뜻이 아니다**. |
| `unknown`       | 시간 초과, 결정 불가능한 조각(양화사, 비선형 산술) 등으로 판단하지 못했다.                      |

**`found`의 근거.** 다음이 성립하므로, $M \models \Gamma$, $M \models U$, $M \not\models A$이면 $A$는 $\Gamma$, $U$(`using`으로 준 전제), 표준 공리로부터 L0–L3 규칙으로 도출되지 않는다.

1. L0–L2의 모든 규칙은 비어 있지 않은 정의역과 표준 등식을 갖는 고전 다종 구조에 대해 건전하다. L1은 종의 거주성을 가정하지 않으므로([logic-spec.md §12](logic-spec.md#12-단편-l1-일차-술어-논리)), 비어 있지 않은 정의역의 반례만으로 충분하다.
2. `classical.em`의 모든 인스턴스는 모든 고전 구조에서 참이다.
3. `arith.*` 공리의 모든 인스턴스(귀납 스키마 포함)는 표준 자연수 $\mathbb{N}$에서 참이다. 따라서 `arith.Nat`을 $\mathbb{N}$으로 해석한다 (§4.3).
4. 의존 공리가 모두 표준 공리인 `VERIFIED` 정리는 그 모든 인스턴스가 1–3에 따라 $M$에서 참이다. 따라서 그런 정리를 사용해도 목표를 도출할 수 없다.

사용자 공리와, 사용자 공리에 의존하는 정리는 $M$에서 참이라는 보장이 없다. 이들을 전제로 고려하려면 필요한 인스턴스를 `using`에 명시해야 한다. 결과 보고는 고려한 전제의 범위를 함께 표시해야 한다.

`none`은 고전 논리와 $\mathbb{N}$에서의 참을 뜻한다. 직관주의 도출에는 `classical.em`이 필요할 수 있고, 산술 명제는 $\mathbb{N}$에서 참이어도 공리로부터 도출되지 않을 수 있다.

### 4.2. API

```python
result = ctx.counterexample()                       # 현재 목표, 문맥 가정만 사용
result = ctx.counterexample(using=[ctx.thm(lemma)], timeout_ms=2000)

from axiomweave.backends.smt import counterexample
result = counterexample(prop, using=[...])           # 닫힌 명제 (증명 시작 전 점검)
```

| 항목         | 정의                                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 대상         | `ctx.counterexample`은 현재 목표(첫 번째 열린 목표)의 변수, 문맥 가정, 목표 명제를 사용한다. 함수형은 `Prop` 또는 `GoalView`를 받는다. |
| `using`      | 추가 전제. `Fact` 또는 `Prop`의 목록이다. `Fact`의 명제는 현재 목표의 범위 안에 있어야 한다 (`ScopeError`).                         |
| `timeout_ms` | Z3 시간 제한. 기본값 5000.                                                                                                        |
| 부수 효과    | 없다. 목표 목록과 도출을 바꾸지 않으며 인증서에 아무것도 기록하지 않는다.                                                          |
| 반환         | 불변 객체 `Counterexample(status, model, reason, checked)`. `str(result)`는 §4.4 형식이다.                                        |
| Z3 미설치    | `BackendUnavailableError`(`AxwError`의 하위 클래스)를 일으킨다. 메시지에 `uv sync --extra smt`를 안내한다.                         |

- Z3는 선택적 의존성(`smt` extra, 패키지 `z3-solver`)이다. `axiomweave`의 다른 모듈은 Z3 없이 동작해야 하며, `axiomweave.backends.smt`는 Z3를 호출 시점에 가져온다.
- 개발 의존성 그룹에 `z3-solver`를 추가하여 테스트가 기본 개발 환경에서 실행되게 한다. Z3를 가져올 수 없으면 해당 테스트는 건너뛴다.

### 4.3. 인코딩

| AxiomWeave                                                       | Z3                                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------- |
| 종 `S`                                                           | 해석되지 않은 종 (`DeclareSort`)                                     |
| 상수 `c : S₁ → … → S`, 술어 `p : S₁ → … → Prop`                  | 해석되지 않은 함수 (`Function`). 인자가 없으면 상수 (`Const`)         |
| 원자 $P$, 스키마 술어 변수 $P : S_1 \to \dots \to \mathrm{Prop}$ | `Bool` 상수, `Bool`을 돌려주는 함수. 이름과 인자 종의 쌍마다 다른 기호 |
| 목표의 변수 (`intro`로 도입한 항 변수)                           | 해당 종의 상수                                                      |
| $\bot$, $\land$, $\lor$, $\to$                                   | `False`, `And`, `Or`, `Implies`                                     |
| $\forall x{:}S.\,A$, $\exists x{:}S.\,A$                         | `ForAll`, `Exists`                                                  |
| $t =_S u$                                                        | `==`                                                                |
| 문맥 가정, `using`의 명제                                        | 단언 (assert)                                                       |
| 목표 $A$                                                         | `Not(A)` 단언                                                       |

- 목표가 $\forall x{:}S.\,A$로 시작하면, `intro`처럼 앞쪽의 $\forall$ 바인더를 새 자유 변수로 연 뒤 인코딩한다. $\lnot\forall x.\,A$와 새 상수 $c$에 대한 $\lnot A[c/x]$는 충족 가능성이 같으므로 탐색 결과는 바뀌지 않으며, 반례의 증인(witness)이 모델의 상수로 표시된다. 새 이름은 전제와 목표의 자유 변수 이름과 겹치지 않게 고른다.

**표준 산술의 해석.** 정규 이름이 `arith.Nat`인 종은 $\mathbb{N}$으로 해석한다. `arith.zero`, `arith.succ`, `arith.add`, `arith.mul`은 정규 이름과 인자·결과 종이 표준 Theory `arith`의 선언과 같으면 다음과 같이 해석한다. 표준 공리를 쓸 수 있는 환경에서는 커널이 공리의 명제를 이 선언들에 대해 타입 검사하므로, 네 상수는 항상 표준 해석을 받는다.

| 기호                                        | Z3                             |
| ------------------------------------------- | ------------------------------ |
| `arith.Nat`                                 | `Int`, 값은 0 이상으로 제한    |
| `zero`, `succ(t)`, `add(t, u)`, `mul(t, u)` | `0`, `t + 1`, `t + u`, `t * u` |

- `Nat`의 양화사는 범위를 제한한다: $\forall x{:}\mathrm{Nat}.\,A$는 `ForAll x. x >= 0 → A`, $\exists x{:}\mathrm{Nat}.\,A$는 `Exists x. x >= 0 ∧ A`이다.
- `Nat`을 돌려주는 해석되지 않은 기호(상수, 함수, 목표의 변수) $g$는 `Int`를 돌려주는 기호 $h$의 절댓값 `If(h ≥ 0, h, -h)`로 인코딩한다. $\mathbb{N}$으로 가는 모든 함수가 이 꼴이므로 모델을 잃지 않으며, 범위를 위한 양화 단언이 필요 없다.
- 표준 해석을 받지 않는 `arith.*` 상수는 다른 상수처럼 해석되지 않은 기호로 인코딩한다.

### 4.4. 모델 표시와 결정성

```text
counterexample found (Z3 4.x; premises: context)
  U = {U#0, U#1}
  a = U#0
  Even(U#0) = false
  Even(U#1) = true
  P = false
  n = 1
```

- 해석되지 않은 종의 원소는 `S#i`로 표시한다. `i`는 Z3가 돌려준 원소 순서이다.
- 함수와 술어는 표시된 원소에 대한 값표로 나타낸다. `Nat` 인자를 갖는 함수는 정의역이 무한하므로, 모델의 `Nat` 상수 값과 Z3 해석에 나열된 점에서의 값만 표시한다.
- 재검산을 하지 못한 모델은 머리줄에 `not re-checked`를 붙인다.
- 같은 입력과 같은 Z3 버전에 대해 결과가 같도록 Z3의 무작위 시드를 고정한다. 다른 Z3 버전에서는 다른 (그러나 똑같이 유효한) 모델이 나올 수 있다.

### 4.5. 모델 재검산

Z3와 인코딩은 비신뢰 계층이다. 따라서 `found`인 모델은 가능한 경우 인코딩과 독립적인 Python 평가기로 다시 확인한다.

- 모든 해석되지 않은 종이 유한 정의역을 갖고 `Nat`을 범위로 하는 양화사가 없으면, 평가기는 AxiomWeave 명제를 모델에서 직접 평가하여 모든 전제가 참이고 목표가 거짓임을 확인한다. 확인되면 `checked = True`이다.
- 평가할 수 없는 모델(예: `Nat` 양화사)은 `checked = False`로 보고한다.
- 평가기가 Z3와 다른 결론을 내면 결과는 `unknown`이며, `reason`에 불일치를 기록한다. 이는 인코딩 결함 신호이다 (§1 원칙 4).

### 4.6. 예제

예제는 비규범적이다.

```python
@thy.proof(even_somewhere)               # ⊢ ∃x:U. Even(x)   (가정 없음)
def _(ctx):
    print(ctx.counterexample())
    # counterexample found (...): U = {U#0}, Even(U#0) = false

@thy.proof(lem)                          # ⊢ P ∨ ¬P
def _(ctx):
    print(ctx.counterexample().status)   # none: 고전적으로 참. 증명에는 classical.em이 필요하다.

counterexample(ForAll(n, Eq(add(n, n), n)))   # ∀n:Nat. n + n = n → found: n = 1
counterexample(ForAll([m, n], Eq(add(m, n), add(n, m))))   # none: ℕ에서 참 (증명에는 귀납이 필요하다)
```

### 4.7. 범위 밖

- CLI 명령(`axw counterexample` 등)과 증명 실패 진단에 반례를 자동으로 붙이는 기능은 포함하지 않는다.
- SMT 응답을 증명으로 재구성하는 기능(§6)은 포함하지 않는다.

## 5. SymPy 산술 정규화

> **상태:** 확정 · 구현됨. 이 절은 SymPy를 사용하여 자연수 다항식 등식을 판정하고, 그 등식을 커널 도출로 재구성하여 증명하는 전술을 정의한다. 새 커널 규칙이나 공리를 추가하지 않는다.

### 5.1. 목적과 지위

`arith`의 덧셈과 곱셈만으로 이루어진 등식, 예를 들어 $(m+n)(m+n) = m m + 2 m n + n n$은 귀납과 다시 쓰기로 증명할 수 있지만 단계가 길다. 이 절의 전술은 이런 다항식 항등식을 한 번에 증명한다.

| 역할            | 담당                              | 신뢰                                                                            |
| --------------- | --------------------------------- | ------------------------------------------------------------------------------- |
| 항등식 판정     | SymPy (`expand`)                  | 비신뢰. 잘못된 판정은 전술 실패로 이어질 뿐, 잘못된 증명을 만들지 않는다.        |
| 실패 진단       | SymPy (두 변의 차 다항식)         | 비신뢰. 오류 메시지에만 쓴다.                                                   |
| 증명            | AxiomWeave 정규화기 (§5.5)        | 비신뢰. 만든 도출을 커널이 검사한다.                                            |

- 결과 정리는 일반 정리와 같이 `VERIFIED`가 되며, 의존 공리 집합은 재구성에 실제로 쓰인 `arith.*` 공리이다. `classical.em`에 의존하지 않는다.
- **판정의 근거.** 자연수 계수 다항식 두 개가 모든 자연수 대입에서 같으면 다항식으로서 같다 (무한 정의역). 또 가환 반환(commutative semiring)의 자유 대상은 $\mathbb{N}[X]$이므로, 다항식으로서 같은 두 항은 가환 반환 법칙만으로 같다고 도출된다. 이 법칙은 모두 `arith`의 정리이다 (§5.5). 따라서 이 전술은 그 대상 항(§5.2)에 대해 완전하다.

### 5.2. 대상 항

종 `arith.Nat`의 항을 다음과 같이 다항식으로 읽는다.

| 항                         | 다항식                     |
| -------------------------- | -------------------------- |
| `zero`                     | $0$                        |
| `succ(t)`                  | $t + 1$                    |
| `add(t, u)`, `mul(t, u)`   | $t + u$, $t \cdot u$       |
| 그 밖의 항 (변수, 다른 상수의 적용) | 원자(atom). 같은 원자는 같은 변수이다. |

- 원자의 동일성은 항의 구문적 동일성이다. 서로 다른 상수 기호는 짧은 이름이 같아도 다른 원자이다.
- `g(m + n)`과 `g(n + m)`처럼 인자만 다른 원자는 다른 변수로 다룬다. 원자 안의 항은 정규화하지 않는다.
- 문맥의 가정은 사용하지 않는다. 가정이 필요한 등식은 `rewrite` 등으로 먼저 목표를 바꾼다.

### 5.3. API

| 전술 / 연산               | 현재 목표              | 결과                                                                       |
| ------------------------- | ---------------------- | -------------------------------------------------------------------------- |
| `ctx.ring()`              | $t =_{\mathit{Nat}} u$ | 목표를 닫는다                                                              |
| `ctx.ring_eq(t, u)`       | (임의)                 | $t = u$인 `Fact`를 돌려준다. $t$, $u$는 현재 목표의 범위 안에 있어야 한다 (`ScopeError`) |

| 상황                                                       | 오류                       |
| ---------------------------------------------------------- | -------------------------- |
| 목표가 `arith.Nat`의 등식이 아님, 항의 종이 `arith.Nat`이 아님 | `TacticError`              |
| 다항식 항등식이 아님                                       | `TacticError`. 메시지에 SymPy가 계산한 차 $t - u$를 포함한다 (예: `lhs - rhs = 2*m*n`) |
| 정규형이 크기 제한(§5.5)을 넘음                            | `TacticError`              |
| SymPy는 항등식이라 했으나 재구성에서 두 정규형이 다름      | `TacticError`. 결함 신호로 메시지에 명시한다 (§1 원칙 4) |
| 현재 Theory 환경에 `arith`가 없음                          | `DeclarationError`         |
| SymPy가 설치되지 않음                                      | `BackendUnavailableError` (`uv sync --extra symbolic` 안내) |

- 전술은 `arith`의 정리와 공리를 `ctx.induction()`처럼 정규 이름으로 현재 Theory의 환경에서 찾는다.
- SymPy는 선택적 의존성(`symbolic` extra, 패키지 `sympy`)이며 호출 시점에 가져온다. 개발 의존성 그룹에도 추가하여 테스트가 기본 개발 환경에서 실행되게 한다.

### 5.4. 판정

1. 두 변을 §5.2에 따라 다항식으로 읽는다. 원자마다 SymPy 기호(`Symbol`, `integer=True, nonnegative=True`)를 하나씩 둔다. 기호 이름은 원자의 등장 순서에 따른 `a0`, `a1`, …이며, 오류 메시지에서는 원자의 표시(`str(term)`)로 바꾸어 보여 준다.
2. `sympy.expand(T - U) == 0`이면 항등식으로 판정하고 §5.5의 재구성을 한다. 아니면 재구성 없이 `TacticError`를 일으킨다.

### 5.5. 재구성

재구성은 SymPy와 독립적인 Python 정규화기가 한다. 정규화기는 각 변 $t$에 대해 $t = \mathrm{nf}(t)$의 도출을 만들고, $\mathrm{nf}(t)$와 $\mathrm{nf}(u)$가 구문적으로 같으면 대칭과 추이로 $t = u$를 얻는다.

**정규형.** $\mathrm{nf}(t)$는 단위 단항식의 합이다. 계수 $c$는 같은 단위 단항식을 $c$번 더한 것으로 나타내므로, 재구성에 수(numeral) 계산이 필요 없다.

- 단위 단항식은 원자들의 곱이다. 원자는 고정된 전순서로 정렬하여 왼쪽으로 결합한 `mul`로 쓴다. 원자가 없는 단위 단항식(상수 1)은 `succ(zero)`이다.
- 다항식은 단위 단항식을 고정된 전순서(차수, 그다음 원자 열)로 정렬하여 왼쪽으로 결합한 `add`이다. 빈 합은 `zero`이다.
- 원자의 순서는 정규 이름을 쓰는 원자 키로 정하며, 같은 입력에 대해 결정적이다. 정규형의 구체적 모양은 사용자에게 노출하지 않는다.
- 정규화기는 덧셈을 삽입 정렬로, 곱셈을 분배 후 단항식 곱으로 계산하며, 각 단계를 아래 정리의 인스턴스와 `congr`로 증명한다.

**사용하는 정리.** 도출은 $\mathrm{Eq}\text{-refl}$, $\mathrm{Eq}\text{-E}$ (기존 `symm`, `trans`, `congr`의 도출)와 다음 `arith` 정리의 인스턴스로만 이루어진다. 추가된 정리는 `lib.arithmetic.peano`에서 귀납으로 증명된다 ([language-spec.md §14.3](language-spec.md#143-표준-theory-arith)).

| 정리                                   | 명제                                              | 상태   |
| -------------------------------------- | ------------------------------------------------- | ------ |
| `add_zero`, `mul_zero`                 | 공리                                              | 기존   |
| `zero_add`, `add_comm`, `add_assoc`    | 정리                                              | 기존   |
| `add_right_comm`                       | $(k + m) + n = (k + n) + m$                       | 추가됨 |
| `succ_eq_add_one`                      | $S(n) = n + 1$                                    | 추가됨 |
| `zero_mul`, `succ_mul`                 | $0 \cdot n = 0$, $S(m) \cdot n = m \cdot n + n$   | 추가됨 |
| `mul_one`, `one_mul`                   | $n \cdot 1 = n$, $1 \cdot n = n$                  | 추가됨 |
| `mul_comm`, `mul_assoc`                | $m n = n m$, $(k m) n = k (m n)$                  | 추가됨 |
| `mul_right_comm`                       | $(k m) n = (k n) m$                               | 추가됨 |
| `mul_add`, `add_mul`                   | $k(m + n) = km + kn$, $(k + m)n = kn + mn$        | 추가됨 |

`succ_mul`은 `mul_comm`의 증명에 쓰이는 보조 정리이다.

**크기 제한.** 정규화의 각 단계가 다항식 전체를 다시 기술하므로, 인증서의 크기는 단위 단항식 수에 대해 대략 세제곱으로 커진다. 정규화기는 덧셈·곱셈을 계산하기 전에 결과의 크기를 예측하여, 다음 제한을 넘으면 재구성하지 않고 `TacticError`를 일으킨다. 제한은 `axiomweave.language.ring`의 모듈 상수이다.

| 항목                                                     | 기본 제한 |
| -------------------------------------------------------- | --------- |
| 단위 단항식 수 (계수의 합. 중간 결과 포함)               | 40        |
| 단항식의 차수                                            | 8         |

- 참고 측정 (비규범): $(m+n)^5$ (32개)은 약 1.5초, $(m+n)^6$ (64개)은 약 10초가 걸린다.

### 5.6. 예제

예제는 비규범적이다.

```python
two = numeral(2)

@thy.theorem
def square() -> Prop:
    return ForAll([m, n], Eq(mul(add(m, n), add(m, n)),
                             add(add(mul(m, m), mul(two, mul(m, n))), mul(n, n))))

@thy.proof(square)
def _(ctx):
    ctx.intro()
    ctx.intro()
    ctx.ring()                    # VERIFIED, 의존 공리 ⊆ arith.*

@thy.proof(wrong)                 # (m + n)(m + n) = m m + n n
def _(ctx):
    ctx.intro()
    ctx.intro()
    ctx.ring()                    # TacticError: not a polynomial identity: lhs - rhs = 2*m*n
```

### 5.7. 범위 밖

- 뺄셈, 나눗셈, 순서($\le$)와 부등식, 가정을 사용하는 산술(선형 산술 결정 절차)은 포함하지 않는다.
- SymPy로 등식 후보를 찾거나 인수분해하여 목표를 제안하는 기능은 포함하지 않는다.
- 정규형을 돌려주는 연산(`ring_nf`)은 포함하지 않는다.

## 6. 이후 연계 (비규범)

- **가져오기:** Lean에서 증명된 명제를 `EXTERNAL_VERIFIED`로 기록하는 경로는 Lean 증명 항을 커널 도출로 재구성할 수 있는 단편에서만 `VERIFIED`로 올릴 수 있다 ([specification.md §6](specification.md#6-검증-상태)).
- **SMT (Z3, cvc5):** 반례 탐색(§4) 외에, 명제 논리 목표의 탐색을 돕는다. 솔버의 응답은 커널 도출로 재구성되기 전에는 증명으로 쓰지 않는다.
- **SymPy:** 다항식 등식 판정(§5) 외에, 인수분해 등으로 등식 후보를 생성한다. 후보 등식은 L2·L3 전술로 다시 증명한다.
